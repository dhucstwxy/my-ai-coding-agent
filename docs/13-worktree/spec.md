# Git Worktree 隔离 Spec

## 背景

子 Agent 已能与主对话并行执行，但仍与主 Agent 共用同一工作区。并行改文件时会互相覆盖，也无法让主 Agent 在派活后互不干扰地继续改主区。上一章已明确不做工作区副本隔离；本步用 Git 自带的多工作目录机制，在同一仓库内为需要隔离的子 Agent 提供独立工作目录。

## 目标

- 同一仓库可挂多个工作目录，共享版本库、各自分支；目录落在仓库内不被追踪的固定位置 `.mewcode/worktrees/<name>/`
- 目录名严格校验，防止路径遍历
- 提供完整生命周期：创建（含已存在时的快速恢复）、进入（绑定显式工作目录，不切换进程全局工作目录）、退出、删除
- 创建后按固定规则做环境初始化
- 路径相关缓存以绝对路径为键，按目录天然隔离
- 定义式角色声明 `isolation: worktree` 时自动建目录并注入路径；结束后按变更情况保留或清理
- 退出与清理有变更保护；后台按固定过期时长与三层过滤清理过期目录

## 功能需求

### 工作目录生命周期

- F1: 提供创建能力：在仓库内 `.mewcode/worktrees/<name>/` 建立 Git 工作目录，从主工作区当前 HEAD 检出新分支（分支名与 `<name>` 按固定规则对应，例如 `mew/<name>`）。创建成功后该目录可独立读写文件，不改动主工作区当前检出。
- F2: 目录名必须通过安全校验：限制允许的字符集与最大长度；路径段不得为 `.` 或 `..`；允许用斜杠表示嵌套；校验失败则拒绝创建/进入/删除，并说明原因，不触碰文件系统与 Git。
- F3: 若目标目录已存在且可识别为既有工作目录：只读取文件系统状态并绑定使用，不再次调用创建类 Git 操作（快速恢复）。若不存在则完整创建。
- F4: 「进入」不修改进程全局工作目录；效果是把该工作目录的绝对路径作为后续操作的显式工作目录。「退出」解除该绑定，后续操作回到主工作区路径。
- F5: 提供删除能力：在通过变更保护后，移除该工作目录及其在 Git 中的工作目录登记。删除失败时说明原因，不留下半删除的模糊状态（能恢复的尽量恢复到可描述状态）。

### 环境初始化

- F6: 新建工作目录成功后，执行固定规则的环境初始化：复制本地配置、为该目录配置 git hooks、对常见大型依赖目录建立软链（若主工作区存在）、按内置规则补齐被忽略但运行需要的文件。快速恢复时若初始化产物已在，不重复破坏性覆盖；缺失的按同一规则补齐。

### 显式工作目录与缓存隔离

- F7: 所有会读写仓库文件或依赖「当前项目根」的工具调用，必须接收显式工作目录参数；不得依赖进程全局工作目录切换来区分主/子目录。
- F8: 文件内容、系统提示、项目指令、记忆等路径相关缓存，一律以绝对路径作为键；不同工作目录下的同名相对路径互不命中、互不覆盖。切换绑定工作目录时不必为隔离而清空这些缓存。

### 子 Agent 隔离模式

- F9: 定义式角色可在元信息中声明 `isolation: worktree`。未声明或声明其他值时，行为与上一章相同：与主 Agent 共用主工作区。Fork 式不使用该声明，始终共用主工作区。
- F10: 带该声明的定义式子 Agent 启动时：系统自动生成合法 `<name>`（模型不可见、不可改），创建或快速恢复对应工作目录，完成环境初始化，将该目录绝对路径注入为该子 Agent 全部工具调用的显式工作目录，并在其可见说明中告知隔离路径（便于它理解自己在独立目录中工作）。
- F11: 该子 Agent 结束后：若工作目录有未提交修改或未推送的本地 commit，则保留目录并跳过自动删除；若工作区干净且无此类未推送 commit，则自动删除。删除失败不影响子 Agent 已返回给父会话的最终结果，但需留下可观察的失败说明（如日志）。

### 变更保护与过期清理

- F12: 任何删除（含结束后的自动删除与显式删除）在检测到未提交修改或未推送的本地 commit 时，默认拒绝删除并说明原因。
- F13: 后台定期扫描 `.mewcode/worktrees/` 下的候选目录：超过 7 天未使用才进入清理候选；清理前依次过滤——仍被视为活跃使用中的跳过；有未提交修改或未推送 commit 的跳过；目录名未通过安全校验或不在该固定根下的跳过。三层都通过才删除。

## 非功能需求

- N1: 目录名校验、变更保护拒绝删除、快速恢复不重复调 Git 创建，不依赖真实远程仓库或网络即可验证。
- N2: 创建、初始化、删除、过期清理中的单次失败只影响该工作目录；不拖垮主 Agent 会话，也不取消其他并行子 Agent。
- N3: 主工作区的当前分支与未提交状态，不因「为子 Agent 创建/删除隔离目录」而被切换或清空；隔离目录内的提交默认也不自动合并回主工作区。
- N4: 显式工作目录绑定出错（路径非法、目录不存在、非预期状态）时，相关工具调用失败并返回明确原因，不得静默回退到主工作区继续写文件。
- N5: 软链或复制初始化单项失败时：记录原因；若导致该隔离目录无法安全使用，则创建/启动失败并清理本次不完整产物（能清则清）；不把半初始化目录交给子 Agent 当可用工作区。
- N6: 过期清理与子 Agent 结束时的自动删除必须可重复执行：对已不存在的目录视为无需再删，不报致命错误。
- N7: 行为可用本地 Git 仓库做端到端观察（建目录、并行改不同文件、结束后保留/删除）；不要求接真实大模型即可完成核心路径的自动化检查。

## 不做的事

- 不做 Worktree 之间或 Worktree 与主工作区之间的自动合并策略；需要合并时由上层自行用 Git 合并决定
- 不做跨工作目录的代码/文件自动同步
- 不做多 Agent 并行编排、编队调度或任务看板（留给后续团队协作章节）
- 不让 Fork 式子 Agent、未声明隔离的定义式子 Agent 走 Worktree；它们仍与主 Agent 共用主工作区
- 不通过修改进程全局工作目录来切换上下文
- 不把隔离目录的 `<name>` 暴露给模型填写或修改
- 不在本步实现可配置的过期时长、可配置的复制/软链清单（采用固定规则与固定 7 天）
- 不保证所有操作系统上软链能力完全一致时的降级策略产品化（若环境无法建立软链，按 N5 视为初始化失败，不另做拷贝整棵大型依赖目录的兜底）

## 验收标准

- AC1: 在合法 `<name>` 下创建后，仓库内出现 `.mewcode/worktrees/<name>/`，且该目录是独立 Git 工作目录；主工作区当前分支与文件内容未被切换或清空。（F1）
- AC2: 含 `.` / `..` 段、非法字符或超长的 `<name>` 被拒绝；拒绝时无新目录、无新的 Git 工作目录登记。（F2）
- AC3: 对已存在的合法隔离目录再次「创建/进入」时，不重新执行 Git 新建工作目录；仍能绑定到该目录绝对路径并正常使用。（F3）
- AC4: 「进入」后工具读写落在隔离目录；进程全局工作目录保持不变。「退出」后工具读写回到主工作区。（F4、F7）
- AC5: 隔离目录工作区干净且无未推送本地 commit 时，删除会去掉该目录及其 Git 工作目录登记；有未提交修改或未推送 commit 时删除被拒绝并说明原因，目录仍在。（F5、F12）
- AC6: 新建成功后，隔离目录内具备固定规则下的本地配置副本、hooks 配置、大型依赖软链（主区存在时）以及规则要求的被忽略文件；缺一项且导致不可用时，不会把该目录当作成功结果交给调用方。（F6、N5）
- AC7: 主区与隔离目录下各写同一相对路径的不同内容时，两侧文件内容互不影响；以绝对路径为键的缓存互不命中。（F8）
- AC8: 角色声明 `isolation: worktree` 的定义式子 Agent 启动后，其文件类工具操作发生在新建或恢复的隔离目录中；未声明角色与 Fork 仍操作主工作区。（F9、F10）
- AC9: 声明隔离的子 Agent 运行期间，模型侧看不到、也不能指定 `<name>`；系统生成的名称通过校验且落在 `.mewcode/worktrees/` 下。（F10）
- AC10: 该子 Agent 结束后：隔离目录有未提交修改或未推送 commit 则目录保留；干净则目录被自动删除。自动删除失败时，父会话仍能收到子 Agent 最终结果，并有可观察的失败说明。（F11）
- AC11: 放置超过 7 天未使用、且通过三层过滤的目录，会被后台清理删掉；仍在活跃使用、有未提交/未推送、或路径不安全的目录不会被删。（F13）
- AC12: 在无网络、可用本地 Git 的环境下，能完成创建、校验拒绝、变更保护拒绝删除、主/隔离目录并行改文件不互相覆盖的观察或自动化检查。（N1、N3、N7）
