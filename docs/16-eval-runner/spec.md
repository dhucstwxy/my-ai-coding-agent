# Eval Runner Spec

## 背景

已有固定评测集（评测清单 + 20 个自包含 fixture），单题可用验证命令客观判定通过/失败。但仍需人工：复制工作区、在交互界面中喂入任务提示、再跑验证、手填分数。无法一键得到可量化的评测报告。

评测器的核心职责是将 Agent 的执行结果转化为可量化指标。本轮交付最小可跑通版本：串行 headless 跑题、自动权限放行、三项核心/解释性指标、结构化报告。不一次实现图示中的全部六项指标。

## 目标

- 提供评测 CLI 子命令，支持跑全量或指定单题。
- 对每题：复制隔离工作区 → 非交互执行 Agent（读取任务提示）→ 执行验证命令 → 记录结果。
- 评测期间工具权限自动放行，避免交互阻塞。
- 将报告写入带时间戳的运行目录，并在终端打印摘要。
- 汇总指标仅含：
  - Task Success Rate（通过题数 / 本批总题数）
  - Average Latency（各题 Agent 墙钟耗时均值）
  - Average Steps（各题主循环迭代轮数均值）
- 本轮不实现：Tool Success Rate、独立 Test Pass Rate、Cost per Task。

## 功能需求

- F1: CLI 入口。提供评测子命令。默认跑题库全部任务；支持按任务 ID 只跑一题。非法 ID 时明确报错并以非 0 退出。
- F2: 加载题库。从既有评测集清单加载任务元数据（ID、类别、难度、fixture 路径、提示文件、验证命令）。
- F3: 隔离工作区。每题将 fixture 复制到独立工作区再执行；不直接改写题库原件。工作区路径写入报告便于排错。
- F4: Headless 执行 Agent。在工作区内以非交互方式启动 Agent，将任务提示文件内容作为用户任务输入；使用当前项目有效的模型/供应商配置。
- F5: 评测权限策略。评测会话内工具调用自动允许，不弹出权限确认。
- F6: 断言验证。Agent 结束后在工作区执行该题验证命令；退出码 0 记为任务成功，否则失败。
- F7: 单题度量采集。每题至少记录：任务 ID、是否成功、墙钟耗时（毫秒）、主循环迭代步数、失败时的简要原因。
- F8: 汇总指标。基于本批实际执行的题目计算 Task Success Rate、Average Latency、Average Steps。
- F9: 报告输出。写入 `tests/eval/runs/<timestamp>/eval-report.json`；终端打印通过数、三项汇总指标、失败任务 ID 列表。
- F10: 顺序执行。第一版按任务列表串行执行。
- F11: 区外探针题兼容。跑依赖区外探针的题目时，确保约定位置存在内容正确的探针文件，否则该题失败并说明原因。

## 非功能需求

- N1: 可重复结构。同一题库、同一报告结构；分数判定不依赖 LLM 自评。报告记录所用供应商/模型标识（若配置可得）。
- N2: 隔离性。单题工作区互不共享可变状态；评测不得污染题库原件。
- N3: 超时。单题 Agent 执行与验证均有超时上限（可配置并带合理默认）；超时记为该题失败并继续后续题目。
- N4: 依赖。验证前若工作区缺少依赖，runner 负责在该工作区安装；安装失败记为该题失败。
- N5: 可观测。串行跑批时终端显示当前题 ID 与进度；结束后有摘要。
- N6: 安全边界。自动放行仅作用于评测会话；不得把评测自动放行设为日常交互默认权限模式。
- N7: 文档。更新评测说明：如何运行、报告路径、三项指标含义、权限自动放行说明。

## 不做的事

- 不实现 Tool Success Rate、独立 Test Pass Rate、Cost per Task（及模型单价表）。
- 不做并发行题。
- 不改既有题目业务题面与断言语义（仅允许补充 runner 所需的探针/路径说明）。
- 不把评测自动放行变成日常交互默认权限。
- 不实现基于 LLM 的文字评价作为通过条件。
- 不做评测结果上传或排行榜。
- 不实现终端界面内嵌评测面板。
- 不保证跨模型分数可复现（只保证判定规则与报告结构稳定）。

## 验收标准

- AC1: 评测 CLI 可跑全量；指定合法任务 ID 只跑一题；非法 ID 非 0 退出并有错误信息。（F1）
- AC2: 跑题后题库原件不变；实际修改发生在隔离工作区。（F2、F3）
- AC3: Headless 跑题过程中不出现需人工确认的权限提示；在自动放行下能执行到结束或超时。（F4、F5）
- AC4: 验证管道能区分成功与失败产物（正确产物验证成功，未解题初始态验证失败）。（F6）
- AC5: 报告含每题成功标记、耗时、步数；汇总三项指标与明细计算一致。（F7、F8）
- AC6: 每次运行生成带时间戳目录下的 `eval-report.json`；终端有摘要。（F9）
- AC7: 全量运行串行执行，进度可观察。（F10）
- AC8: 探针缺失时相关题失败且原因可辨；探针正确时验证可执行。（F11）
- AC9: 单题超时会失败并继续后续题；日常交互默认权限不被改为自动全放行。（N3、N6）
- AC10: 说明文档覆盖运行方式、报告位置与三项指标含义。（N7）
