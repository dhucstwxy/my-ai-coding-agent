# 会话审批与扩展能力 Spec

## 背景

会话和聊天页已经能按工作区连续对话。每一轮仍是精简执行：只有六个内置工具，调用自动放行，没有 MCP、技能和 Hooks。

终端里的一轮会读取权限规则，在默认档下让只读工具直接通过，有副作用的工具停下来问人。询问的结果可以是拒绝、仅本次放行、本会话放行或永久放行。技能由模型加载，Hooks 按生命周期触发，MCP 在这一轮里提供额外工具。这些都还没有接到会话这一路上。

一次性任务已经被人用来提交后等待结果。它没有旁边的人可以点允许。

## 目标

- 会话的每一轮，以及聊天页上的发送，具备与终端同一轮相同的 MCP、模型可加载的技能和 Hooks。
- 会话这一路使用与终端相同的默认权限档：没有规则命中时，只读工具直接放行，有副作用的工具停下来问。已写明的规则和不可绕过的安全检查仍然生效。
- 需要询问时，聊天页展示工具和参数，并提供拒绝、仅本次放行、本会话放行、永久放行。在选择之前不执行该工具。
- 这一轮结束前没有回答，就视为拒绝这一次。工具不执行，对话继续。
- 本会话放行在这段对话的后续轮次里仍然有效，服务进程或执行进程退出后失效。永久放行写入与终端相同的本地规则。
- 一次性任务保持六个内置工具和自动放行，不出现询问。

## 功能需求

- F1: 会话的每一轮，包括从聊天页发送的那一轮，在开始时按该工作区与终端相同的配置装上 MCP、可供模型加载的技能和 Hooks。这一轮结束时释放这些连接。某一项装不上时，这一轮仍然开始，已经装上的能力仍可使用，并给出可读警告。
- F2: 没有配置 MCP、技能或 Hooks 时，会话这一轮仍能用六个内置工具完成。模型在这一轮里可以发现并加载技能。聊天页不提供斜杠命令。
- F3: 会话这一轮从默认权限档开始，聊天页不能切换档位。没有规则命中时，无副作用的只读工具直接放行，有副作用的工具停下来询问。MCP 工具按有副作用处理。已经写明的允许、询问和拒绝规则，以及危险命令拦截和路径限制，判断顺序和结果与终端相同。这几项安全检查不能被任何放行选择绕过。
- F4: 判断结果是询问时，暂停这一次工具执行。事件流里能看到工具名、将要执行的对象和参数摘要，以及四个选择：拒绝、仅本次放行、本会话放行、永久放行。在收到选择之前不执行该工具。同一轮里同时最多只有一个未完成的询问。
- F5: 拒绝只拒绝这一次，不写入永久拒绝。仅本次放行只放行这一次。本会话放行记住「该工具加上这次的精确参数」，同一段对话的后续轮次里再遇到相同调用时不再询问；服务进程或执行进程退出后，这些记忆失效。永久放行把同样的精确允许写入与终端相同的本地规则，之后终端和会话都会遵守。
- F6: 这一轮结束前没有收到选择，包括超时、取消或执行已经停止，就把这次未完成的询问当作拒绝这一次。该工具不执行。若这一轮仍在进行，拒绝结果交回模型，模型可以改用别的做法，这一轮不因此结束。若这一轮已经结束，对话不再处于忙，可以再发下一条。
- F7: 订阅开始得晚时，仍能看到尚未回答的询问，并可以提交选择。对已经结束的询问或不属于这一轮的选择，提交被拒绝并说明原因，原来的结果不变。
- F8: 聊天页在这一轮的输出里展示询问，并提供上述四个选择。提交后询问消失，事件流继续。这一轮先结束时，页面表明这次询问已按拒绝处理，不再停在等待选择。
- F9: 一次性任务仍只有六个内置工具，调用自动放行。它不装 MCP、技能和 Hooks，事件流里不出现询问，也不能替会话提交选择。

## 非功能需求

- N1: 询问随这一轮的事件流出现，聊天页不能等到整轮结束才显示它。选择提交后，后续正文和工具活动继续增量出现。
- N2: 等待选择时，服务仍能列出和打开对话，也能接受其他空闲对话的新消息。同一段对话在这一轮结束前仍然算忙。
- N3: 未完成的询问最多等到这一轮原有的结束条件，不另设更长的等待。结束条件与会话这一轮现有的超时、取消和执行停止相同。
- N4: 提交选择使用与会话发送相同的访问限制。未授权时不能代替这一轮作出选择。
- N5: 审批展示里不出现配置中的密钥、MCP 的环境变量值或请求头的值。参数摘要只保留判断这次调用所需的对象和简短说明。
- N6: 本会话放行只留在这次服务进程的内存里，不写入对话文件，也不进入一次性任务。永久放行只写入终端已经使用的本地规则，不另建一份。
- N7: 单个 MCP、技能或 Hook 失败时，给出可读的中文警告，服务进程不退出。权限拒绝和未回答也是一样。
- N8: 只使用一次性任务的调用方无需改动。他们的事件流里不增加必须处理的询问。
- N9: 聊天页仍用现有本地页面完成询问和四个选择。新增文案使用中文。

## 不做的事

- 不改一次性任务。它仍是六个内置工具、自动放行，不装 MCP、技能和 Hooks，也不出现询问。
- 不接入小组、子代理，也不改终端交互界面。
- 聊天页不增加斜杠命令，也不提供权限档位切换。
- 不把助手循环或 MCP 连接留到下一句。每轮结束就释放。
- 本会话放行不写入对话文件。服务进程或执行进程退出后不恢复。
- 不为询问另设比这一轮更长的等待，也不在安全检查已经拒绝之后再问人。
- 永久放行不自动放宽成更宽的模式，仍只记下这次调用的精确参数。
- 不新做一套权限规则。判断顺序、黑名单、路径限制和本地规则的写法与终端保持一致。
- 不把网页对话和终端对话合并。
- 聊天页不新增取消、删除、重命名或分叉对话。审批只多出四个选择。

## 验收标准

- AC1: 会话这一轮在配置了 MCP、技能和 Hooks 时能够用上它们。其中一项装不上时，这一轮仍开始，已经装上的能力仍可用，并出现可读警告。这一轮结束后，对应的 MCP 连接不再保留。（F1、N7）
- AC2: 工作区没有 MCP、技能和 Hooks 配置时，会话仍能用六个内置工具完成一轮。聊天页上看不到斜杠命令入口。（F2）
- AC3: 会话中，没有规则命中时，只读工具直接执行，不出现询问。写文件、改文件、执行命令和 MCP 工具会停下来询问，并在选择前不执行。（F3、F4）
- AC4: 危险命令或越出工作区的路径被直接拒绝，四个放行选择都不能让它执行。（F3）
- AC5: 询问出现在事件流里，包含工具名、对象、参数摘要和四个选择。晚订阅仍能看到未完成的询问并提交选择。聊天页上四个选择为中文，提交后询问消失，后续输出继续增量出现。（F4、F7、F8、N1、N9）
- AC6: 拒绝和仅本次放行都只作用于这一次。拒绝后模型还能继续这一轮。本会话放行后，同一段对话的下一轮再遇到相同调用时不再询问；另一段对话仍会询问。重启服务进程或执行进程后，本会话放行失效。（F5、F6、N6）
- AC7: 永久放行后，终端的后续会话和 HTTP 会话对这次精确调用都不再询问。放行记录与终端写在同一处本地规则里，且只包含这次的精确参数。（F5、N6）
- AC8: 询问一直无人回答，直到这一轮超时、取消或执行停止。该工具没有执行，结果按拒绝这一次处理。对话不再处于忙，可以再发下一条。（F6、N3）
- AC9: 对已结束的询问，或对不属于这一轮的选择提交回答，会被拒绝并说明原因，原结果不变。（F7）
- AC10: 等待选择时，其他空闲对话仍能发送并排队。同一段对话再发新消息仍被拒绝为正忙。（N2）
- AC11: 开启与会话发送相同的访问限制后，不带凭证不能提交选择。健康检查仍可访问。（N4）
- AC12: 审批展示和事件流里不出现配置密钥、MCP 环境变量的值或请求头的值。（N5）
- AC13: 一次性任务仍自动放行六个内置工具，事件流里没有询问，也不能提交选择。原有的提交、等待、查询、取消和事件流行为不变。（F9、N8）
- AC14: 聊天页在这一轮先结束时，表明该询问已按拒绝处理，不再停在四个选择上。（F8）
