# 会话审批与扩展能力 Plan

## 架构概览

会话的每一轮走一条新的执行路径。一次性任务仍走现在的无头执行，不装 MCP、技能和 Hooks，也不询问。

新路径在一轮开始时，按该工作区读取与终端相同的权限规则、技能、Hooks 和 MCP，并把权限档设为默认。这一轮结束时关掉 MCP，并结束这一轮的 Hooks。执行进程里按对话标识保留本会话放行；进程退出后这些记忆消失。永久放行调用终端已经在用的本地规则写入。

需要询问时，执行进程暂停这一次工具调用，沿这一轮现有的事件流送出工具名、对象、参数摘要和四个选择。HTTP 服务把选择送回执行进程。没人在这一轮结束前回答，执行进程自行按拒绝这一次继续，不另加等待时限。

| 组件 | 职责 |
| --- | --- |
| 会话一轮 | 只服务带对话标识的会话发送。装上规则、技能、Hooks 和 MCP，使用默认档。询问时暂停工具，直到选择到达或这一轮结束 |
| 无头执行 | 保持现状。六个内置工具，自动放行，不读取会话放行记忆 |
| 本会话记忆 | 留在执行进程内存里，键是对话标识加上工具和精确参数。服务进程或执行进程退出后清空 |
| 事件流 | 仍是这一轮任务的现有事件流。新增询问事件；晚订阅能看到尚未回答的那一条 |
| 选择入口 | 与会话发送使用同一套访问限制。只接受这一轮当前未完成的询问。结束后再提交会被拒绝 |
| 聊天页 | 在这一轮输出里画出询问和四个中文选择。提交后继续看事件流。这一轮先结束时，把未答询问显示为已拒绝 |

```
会话发送
  → 现有队列轮到它
  → 会话一轮装上扩展能力，档位为默认
  → 需要询问时向事件流发出询问并暂停该工具
  → 聊天页提交选择，服务转交执行进程
  → 允许则执行，拒绝则把失败交回模型
  → 轮次结束，关闭 MCP

一次性任务
  → 现有无头执行
  → 不产生询问
```

## 核心数据结构

询问沿用终端已经产生的权限询问字段。服务不另造一套规则，只把这一次暂停暴露到事件流上，并把选择送回执行进程。

### 询问事件

出现在这一轮现有的事件流里，事件名为 `approval`。同一轮同时只有一条 `pending`。

| 字段 | 含义 |
| --- | --- |
| `approvalId` | 这一次询问的标识，与执行进程里暂停的那次调用相同 |
| `runId` | 这一轮任务标识 |
| `status` | `pending`、`allowed` 或 `denied` |
| `tool` | 工具名 |
| `subject` | 将要记住的精确对象，例如命令文本或路径 |
| `argsSummary` | 参数的短摘要，不含密钥、环境变量值和请求头 |
| `choices` | 仅 `pending` 时有。固定为 `deny`、`once`、`session`、`permanent` |
| `choice` | 已结束时有，取值同上。无人回答而结束时为 `deny` |

晚订阅会先收到仍处于 `pending` 的那一条。结束后再订阅，收到对应的 `allowed` 或 `denied`，不能再回答。

### 提交选择

`POST /v1/runs/{runId}/approval`

| 字段 | 含义 |
| --- | --- |
| `approvalId` | 要回答的询问 |
| `choice` | `deny`、`once`、`session` 或 `permanent` |

成功时没有新的任务。这一轮从暂停处继续。询问已经结束、标识对不上、或这一轮不是会话一轮时，拒绝并给出中文原因，原来的工具结果不变。一次性任务属于后一种。

### 执行进程协议

现有的 `run` 只给一次性任务。会话一轮使用新的 `session-run`，其余字段与现在的运行请求相同：工作区、提示、会话标识、会话目录、超时。

选择由服务进程写回执行进程：

```text
{ "type": "approval", "requestId", "approvalId", "choice" }
```

执行进程里每个 `requestId` 最多挂起一个询问。取消或这一轮结束时，挂起的询问以 `deny` 解除，不再等待。

### 本会话记忆

沿用现有的会话放行存储：键是对话标识、工具名和精确对象。它放在执行进程里，跨该对话的后续轮次共享，不写入会话文件。服务进程或执行进程退出后，存储随之消失。永久放行仍调用现有的本地规则写入，不新增文件格式。

### 警告

MCP、技能或 Hook 有单项失败时，在这一轮事件流里发一条 `warning`，字段只有可读的 `message`。失败项不进入本轮工具列表，其余能力继续。

## 模块设计

### 会话一轮

**职责：** 只执行带对话标识的一轮。开始时读取与终端相同的权限规则、技能、Hooks 和 MCP，权限档固定为默认。询问通过注入的确认器暂停。结束时关闭 MCP，并结束这一轮的 Hooks。单项失败变成警告，不阻止开始。

**对外接口：** `runSessionTurn(options)`。`options` 含工作区、提示、会话标识、会话目录、超时、取消令牌，以及本进程共享的会话放行存储。返回与现有无头执行相同形态的报告。

**依赖：** 现有权限闸门、技能加载、Hooks、MCP 连接和代理循环。不调用无头执行。

### 执行进程

**职责：** `run` 仍进入无头执行。`session-run` 进入会话一轮。`approval` 只唤醒该 `requestId` 上挂起的那一次询问。取消、超时或进程退出时，把未完成的询问按拒绝解除。会话放行存储挂在进程上，不随单轮创建。

**对外接口：** 现有的按行协议，加上 `session-run` 和 `approval`。

**依赖：** 会话一轮、无头执行。

### 任务队列

**职责：** 会话发送改走 `session-run`。一次性任务仍走 `run`。把执行进程的询问转成事件流上的 `approval`，警告转成 `warning`。提供回答入口：仅当这一轮是会话一轮、询问标识匹配且仍在等待时，才把选择写回执行进程。

**对外接口：** 现有提交不变。新增 `answer_approval(run_id, approval_id, choice)`。

**依赖：** 现有 worker 客户端。不读取权限规则。

### HTTP 接口

**职责：** `POST /v1/runs/{runId}/approval` 使用与会话发送相同的访问限制，把正文交给任务队列。成功不另开一轮。一次性任务、标识不符或询问已结束，返回中文错误。

**对外接口：** 上述一个路由。请求体是 `approvalId` 和 `choice`。

**依赖：** 任务队列、现有令牌校验。

### 聊天页

**职责：** 收到 `pending` 的询问时，在这一轮输出里显示工具名、对象、参数摘要和四个中文按钮。点击后提交选择，按钮消失。收到 `denied` 或 `allowed`，或者这一轮先结束，把未答询问标成已拒绝，不再可点。不增加斜杠命令和档位切换。

**对外接口：** 无。它只订阅现有事件流并调用选择入口。

**依赖：** HTTP 接口。

### 无头执行

**职责：** 保持现状。不接收 `session-run`，不读取会话放行存储。

**对外接口：** 现有的 `runHeadless`。

**依赖：** 无新依赖。

## 模块交互

任务队列决定一条消息走哪条执行路径。会话一轮和无头执行互不调用。选择只从 HTTP 接口进到任务队列，再写给执行进程。

**会话发送。** 队列轮到带对话标识的一轮时，向执行进程写 `session-run`，而不是 `run`。执行进程调用 `runSessionTurn`。它先装权限规则、技能、Hooks 和 MCP，档位设为默认，并使用进程上那份会话放行存储。装载失败的项变成 `warning` 事件，然后仍进入代理循环。

**询问。** 权限闸门需要确认时调用确认器。确认器登记这一次 `approvalId` 并暂停。执行进程把询问交给任务队列，队列向现有事件流发布 `status` 为 `pending` 的 `approval`。聊天页或晚到的订阅者提交 `POST /v1/runs/{runId}/approval`。队列核对这一轮是会话一轮、标识匹配且仍在等待，然后写一行 `approval` 给执行进程。确认器被唤醒，按四个选择走现有闸门：拒绝交回模型，仅本次只放行这一次，本会话写入内存存储，永久写入本地规则。队列再发布 `allowed` 或 `denied`。

**无人回答。** 取消、超时或执行进程退出时，执行进程用 `deny` 解除挂起的确认器，不再等待下一次选择。若循环还在，模型收到拒绝并可以改做法。若这一轮已经结束，队列把对话从忙状态放开。迟到的提交被 HTTP 接口拒绝，不改变已经产生的结果。

**其他对话。** 等待选择期间，队列不占满整个服务。另一段空闲对话仍可入队。同一段对话的新消息仍按现有正忙规则拒绝。全局仍是一次只执行一轮，所以另一段对话会排队，而不是并行执行。

**一轮结束。** `runSessionTurn` 在结束路径上关闭 MCP，并结束这一轮的 Hooks。会话放行存储留在执行进程里，供这段对话的下一轮使用。

**一次性任务。** 队列仍写 `run`。执行进程调用无头执行。这条路径不登记询问。若有人向它提交选择，队列直接拒绝。

**聊天页。** 它只读事件流。看到 `pending` 就画出四个按钮；提交成功后按钮消失。看到该询问的 `denied`，或这一轮的结束事件先到，就把未答询问标成已拒绝。

## 文件组织

无头执行文件不改。会话一轮是新的执行入口，协议和 HTTP 只做转发。

```
src/run/
└── session-turn.ts          — 新建。runSessionTurn：默认档、技能、Hooks、MCP

src/serve/
└── worker.ts                — 修改。分发 session-run 与 approval，进程级会话放行存储

server/mewcode_api/
├── models.py                — 修改。选择请求体
├── worker_client.py         — 修改。发送 approval，会话一轮写 session-run
├── run_manager.py           — 修改。会话发送走 session-run，转发 approval / warning，answer_approval
├── main.py                  — 修改。POST /v1/runs/{runId}/approval
└── static/chat.html         — 修改。四个选择按钮

server/tests/
├── fake_worker.py           — 修改。识别 session-run，可按提示发出询问并接受 approval
└── test_api.py              — 修改。询问、四个选择、一次性任务不接受选择

src/run/runner.ts            — 不改
src/permission/              — 不改。会话放行存储由执行进程持有现成实例
```

终端入口 `src/cli.ts` 不改。本地规则仍写在终端已经使用的位置。

## 技术决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 执行入口 | 会话发送写 `session-run`，一次性任务仍写 `run` | 两条路径的工具和权限不同。分开放在协议上，避免一个开关把询问漏到一次性任务 |
| 能力组装 | 会话一轮自己装规则、技能、Hooks 和 MCP，不调用无头执行 | 无头执行今天固定为放行档且没有这些能力。复用它会把两种行为缠在一起 |
| 权限档 | 会话一轮固定默认档，不提供切换 | 规格要求与终端默认档一致，聊天页不增加档位 |
| 询问怎么等 | 确认器在执行进程里暂停，选择经 HTTP 写回 | 工具在执行进程里跑。服务进程只转发，不自己判断规则 |
| 事件 | 用现有任务事件流的 `approval` 和 `warning` | 晚订阅、文本和工具事件都已经在这条流上。不另开连接 |
| 无人回答 | 取消、超时或执行停止时按 `deny` 解除暂停 | 规格不另设更长等待。拒绝结果沿用闸门把失败交回模型的做法 |
| 本会话放行 | 执行进程里一个共享的现有会话放行存储 | 同一对话的下一轮还能命中。进程退出即失效，不写入会话文件 |
| 永久放行 | 调用现有本地规则写入 | 终端和会话读的是同一份规则，不新建格式 |
| 一次一个询问 | 每个 `requestId` 只挂起一条 | 与规格一致，也和当前全局一次只跑一轮一致 |
| 错误响应 | 找不到任务用现有的 404。不是会话一轮、标识不符或询问已结束，用 409 和中文原因 | 和「这段对话正忙」一样，调用方能区分冲突和参数错误 |
| 技能入口 | 只注册模型可调用的技能工具 | 聊天页不增加斜杠命令 |
| 测试替身 | 假 worker 识别 `session-run`，用约定提示发出询问并接受 `approval` | 不连接真实 MCP 也能验收暂停、四个选择和一次性任务拒绝选择 |
