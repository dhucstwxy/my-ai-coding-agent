# MewCode 工具系统 Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。  
> 默认联调模型：DeepSeek `deepseek-v4-flash`（OpenAI 兼容协议）。端到端按 `AGENTS.md` 优先在 tmux 中观察。

## 实现完整性

- [ ] 六个核心工具均可按名找到并执行（验证：`createDefaultRegistry()` 后对 `read_file` / `write_file` / `edit_file` / `run_command` / `glob_files` / `grep_search` 各执行一次合法调用，均返回 `ToolResult`）（AC1）
- [ ] 注册中心可导出工具定义且请求携带（验证：`toDefinitions()` 含六个 name；用代理/日志或抓请求体确认首次对话请求带 tools）（AC2）
- [ ] 读文件成功与失败结构化（验证：读工作区内已有文本文件得内容；读不存在路径、`../` 越界路径得 `ok: false` 且进程不崩）（AC3）
- [ ] 写文件成功与越界拒绝（验证：写入新路径后再读回一致；写根外路径失败）（AC4）
- [ ] 改文件唯一匹配规则（验证：恰好一处替换成功；0 次与多处时返回清晰错误且文件内容未变）（AC5）
- [ ] 命令执行与超时（验证：简单 echo 类命令能拿到输出；用极短超时制造超时，得到超时失败而非一直挂起）（AC6）
- [ ] glob / grep 在工作区内可用（验证：已知文件名可被 glob 命中；已知内容可被 grep 命中；越界 path 被拒绝）（AC7）
- [ ] 工具失败不崩进程且有中文说明（验证：非法参数、超时、越界等场景均 `ok: false` 或界面中文错误，进程继续）（AC8）
- [ ] 流式工具参数可拼接；损坏参数有解析失败（验证：正常 tool call 能执行；若可构造损坏 JSON 碎片，得到 parse 失败类结果且未误改文件）（AC9）
- [ ] 多工具调用只执行第一个（验证：诱导模型一次回复多个工具，或注入多 call 测试路径；仅第一个执行，界面或回灌含「忽略后续」说明）（AC10）
- [ ] 单次工具回合：执行 → 回灌 → 二次纯文本（验证：读文件后历史有 tool 调用与结果；随后自动流式文本；该次不再成功执行新工具）（AC11）
- [ ] OpenAI 兼容协议工具链路通（验证：DeepSeek 完成「工具 → 执行 → 文本收尾」至少一次）（AC12）
- [ ] Anthropic 协议工具链路通（验证：有密钥时切换 anthropic 完成同上；无密钥则标记跳过并注明原因）（AC12）
- [ ] TUI 展示工具过程（验证：工具回合可见工具名、参数摘要、成功/失败与结果摘要；随后文本仍流式）（AC13）
- [ ] 纯文本回合与第一章一致（验证：不问工具类问题，仅流式文本多轮，无工具块打扰）（AC14）
- [ ] 含工具会话可持久化恢复（验证：完成含工具一轮后退出再启动，历史中可见工具相关记录与后续文本）（AC15）
- [ ] 超大结果截断标明（验证：对超大文件 read 或制造大输出，返回内容含已截断标明）（AC16）

## 集成

- [ ] CLI 注入 workspaceRoot 与默认 Registry（验证：从项目根 `npm start`，工具相对路径相对该目录生效）
- [ ] ChatService 无 tool call 时只落盘一条 assistant 文本（验证：纯文本轮会话 JSON 无多余 tool 消息）
- [ ] ChatService 有 tool call 时落盘顺序为 assistant(toolCalls) → tool → assistant(text)（验证：打开会话 JSON 对照）
- [ ] 第二次请求不带 tools（验证：请求日志/抓包或代码路径确认请求②无 tools 字段；若模型仍试图调工具则不执行）
- [ ] Provider 只消费 ToolDefinition，不依赖具体工具实现（验证：替换/增减 registry 工具后 Provider 源码无需改工具内部逻辑）

## 编译与测试

- [ ] TypeScript 检查通过（验证：`npm run typecheck` 或 `npx tsc --noEmit` 退出码 0）
- [ ] 项目可启动进入 TUI（验证：`npm start` 进入会话选择/对话界面）
- [ ] 若已配置 lint 脚本则通过；未配置则记「未配置，跳过」

## 端到端场景

- [ ] 场景 1（默认 DeepSeek / tmux）：tmux 中启动 → 新建会话 → 输入「请读取 package.json 并总结项目名与脚本」→ 观察调用 `read_file`、TUI 展示工具结果 → 随后流式总结文本 → 退出再启动历史仍在（验证：AC11、AC12 DeepSeek、AC13、AC15）
- [ ] 场景 2（改文件唯一匹配）：准备测试文件 → 让模型做一处唯一替换成功 → 再故意要求匹配多处相同原文 → 见清晰错误且文件未被错误改写（验证：AC5）
- [ ] 场景 3（命令超时）：让模型执行会超时的命令或本地用短超时测 `run_command` → 得到超时失败，输入框可继续（验证：AC6、AC8）
- [ ] 场景 4（越界路径）：要求读取/写入工作区外路径 → 结构化失败，进程不崩（验证：AC3、AC4）
- [ ] 场景 5（纯文本回归）：普通闲聊两轮，行为与第一章一致，无工具块（验证：AC14）
