# MewCode 工具系统 Spec

## 背景

第一章已具备流式多轮对话、会话落盘、Anthropic / OpenAI 双协议。模型目前只能回复文本，无法读写工作区或执行命令。本轮要补上工具系统，让一次用户提问可以触发「选工具 → 执行 → 看结果 → 再生成文本」，从而从聊天机器人迈向可干活的 Agent；真正的多步自动循环仍留后续。

## 目标

- 提供统一的工具抽象：名称、描述、参数 Schema、执行入口
- 落地六个核心工具：读文件、写文件、改文件、执行命令、按模式找文件、搜代码内容
- 集中注册与按名查找，并能转成各协议 API 可识别的工具列表
- 执行带超时与结构化错误，失败不拖垮进程，结果可回给模型
- LLM 客户端能解析流式工具调用（含参数碎片拼接），执行后回灌历史
- 改文件采用「原文唯一匹配替换」；匹配不到或匹配多次时给出明确错误
- 同一次模型回复若含多个工具调用，只执行第一个
- 工具结果回灌后，再请求一次模型，且该次只允许文本回复
- TUI 展示工具名、参数摘要与成功/失败结果
- 文件与命令操作锁定在启动时的当前工作目录内；Shell 不经用户确认直接执行

## 功能需求

- F1: 系统提供统一的工具抽象；每个工具具备：名称、面向模型的描述、参数 Schema、以及可被调用的执行入口
- F2: 提供工具注册中心：可登记工具、按名称查找、列出全部工具，并能导出为模型 API 可识别的工具定义列表
- F3: 内置「读文件」：在工作区内读取指定路径文本内容并返回；路径越界或文件不存在时返回结构化失败信息
- F4: 内置「写文件」：在工作区内创建或覆盖写入指定路径的文本内容；必要时可创建缺失的中间目录；路径越界时失败
- F5: 内置「改文件」：对工作区内已有文件做「旧文本 → 新文本」替换；旧文本必须在文件中恰好出现一次；出现 0 次或多次时返回清晰错误，供模型调整后重试；路径越界或文件不存在时失败
- F6: 内置「执行命令」：在工作区根目录下执行用户/模型给出的命令；捕获标准输出、标准错误与退出码；超时则中止并返回超时失败；本轮执行前不要求用户确认
- F7: 内置「按模式找文件」：在工作区内按 glob 类模式查找文件路径列表并返回（受工作区边界约束）
- F8: 内置「搜代码内容」：在工作区内按文本/正则模式搜索文件内容，返回匹配的文件路径与上下文片段（受工作区边界约束）
- F9: 所有工具执行具备超时与错误处理；异常、超时、参数不合法等均封装为结构化结果（至少含成功/失败标识与可读信息），不得导致进程崩溃
- F10: 工作区根为进程启动时的当前工作目录；相对路径相对该根解析；解析后落在根外的绝对/相对路径一律拒绝
- F11: 流式对话请求可携带已注册工具定义；客户端能解析流式工具调用（含参数 JSON 碎片拼接），得到完整的工具名与参数
- F12: 当模型一次回复包含一个或多个工具调用时，系统只执行其中第一个；其余不执行，并在回给模型/界面的信息中说明「已忽略后续工具调用」
- F13: 工具执行完成后，将「助手的工具调用」与「工具结果」写入对话历史；随后再发起一次模型请求；该次请求不提供工具定义（或等价地禁止再调工具），只收集文本回复并展示
- F14: 若第二次请求中模型仍试图调用工具，系统不执行，并结束本轮（可附简短说明）；用户可见的最终内容以已有文本与已执行工具结果为准
- F15: OpenAI 兼容协议与 Anthropic 协议均支持本轮工具调用链路（带 tools、流式解析、结果回灌）
- F16: TUI 在工具回合中展示：工具名称、参数摘要、执行中/成功/失败状态及结果摘要；第二次模型文本回复仍流式展示
- F17: 无工具调用的纯文本回合行为与第一章一致（流式文本、历史落盘等）

## 非功能需求

- N1: 实现语言与现有项目一致（TypeScript 命令行程序），工具系统接入后仍能在常见桌面终端中启动使用
- N2: 工具失败、超时、参数非法、路径越界、命令非零退出等，一律以结构化结果返回，进程不得因此崩溃；界面给出可读中文说明
- N3: 工具执行有明确超时上限（命令执行尤其需要）；超时后停止等待并返回失败，不得无限挂起输入框
- N4: 读文件、搜内容等输出过大时需截断或限制规模，避免把超大结果整段塞进对话历史导致后续请求失败或界面卡死（截断时须标明已截断）
- N5: 工作区路径约束必须可靠：经规范化后的路径不得逃出启动时的当前工作目录（含 `..`、符号链接导致的逃逸若能检测到则拒绝）
- N6: 流式工具调用解析必须在参数碎片到达过程中可增量拼接，最终得到合法 JSON 或给出「参数解析失败」的结构化错误，不得静默丢弃
- N7: 工具调用与结果写入会话历史后应落盘，进程重启后仍能看到该回合的工具过程与后续文本（与现有会话持久化一致）
- N8: 本轮交付应能在本地用真实（或兼容）API 做端到端验证：至少覆盖「读文件 → 二次文本回复」；开发/验收默认优先 DeepSeek（OpenAI 兼容）；Anthropic 在具备密钥时补充验证工具调用链路
- N9: 中文界面文案与中文代码注释（与项目语言约定一致）

## 不做的事

- 不实现自动多步 Agent Loop（工具结果回来后不自动再调工具；仅允许一次工具执行 + 一次纯文本收尾）
- 不实现同一次回复内的多工具并行/串行全执行（只执行第一个）
- 不实现 MCP、插件市场、自定义用户工具加载
- 不实现子 Agent / 多 Agent 编排
- 不实现命令执行前的用户确认、权限分级、沙箱隔离（本轮仅工作区路径锁定 + 超时）
- 不实现可配置的工作区根目录（固定为启动时的当前工作目录）
- 不实现补丁/diff 应用类编辑器（改文件仅「唯一原文匹配替换」）
- 不实现二进制文件读写、图片等多模态工具
- 不实现网络搜索、浏览器操作等本轮六个工具以外的能力
- 不实现图形界面；仍为终端 TUI
- 不改变第一章已有的配置加载、会话列表/新建、纯文本流式对话的基本体验（仅在其上叠加工具能力）

## 验收标准

- AC1: 存在可被调用的统一工具抽象；六个核心工具均可按名称找到并执行（对应 F1、F2、F3–F8）
- AC2: 注册中心可列出全部工具，并能导出为模型 API 可识别的工具定义列表；请求中实际携带该列表（对应 F2、F11）
- AC3: 在工作区内读已有文本文件，能得到文件内容；读不存在路径或越界路径时，返回结构化失败且进程不崩（对应 F3、F9、F10、N2、N5）
- AC4: 在工作区内写文件可创建/覆盖文本；越界路径被拒绝（对应 F4、F10）
- AC5: 改文件在旧文本恰好出现一次时替换成功；0 次或多次时返回清晰错误，文件内容不被错误改写（对应 F5）
- AC6: 执行命令能拿到 stdout/stderr/退出码；人为制造超时场景时返回超时失败而非一直挂起（对应 F6、N3）
- AC7: 按模式找文件、搜代码内容能在工作区内返回匹配结果；越界模式/路径被约束（对应 F7、F8、F10）
- AC8: 工具超时、参数非法、执行异常均以结构化失败返回，进程不崩溃，界面有可读中文信息（对应 F9、N2）
- AC9: 流式响应中的工具调用参数碎片能拼成完整调用；故意损坏参数时得到解析失败类结构化错误（对应 F11、N6）
- AC10: 模型一次回复含多个工具调用时，只执行第一个；界面或回灌信息中能看到其余被忽略的说明（对应 F12）
- AC11: 工具执行后历史中可见工具调用与结果；随后自动再请求一次模型并流式展示纯文本；该次不再成功执行新的工具（对应 F13、F14、F16）
- AC12: OpenAI 兼容与 Anthropic 协议均可完成至少一次「工具调用 → 执行 → 回灌 → 文本收尾」链路（Anthropic 在有密钥时验证）（对应 F15、N8）
- AC13: TUI 在工具回合展示工具名、参数摘要、成功/失败与结果摘要；随后文本仍流式出现（对应 F16）
- AC14: 不触发工具的纯文本多轮对话行为与第一章一致（对应 F17）
- AC15: 完成含工具的一轮对话后退出再启动，历史中仍能看到该回合工具相关记录与后续文本（对应 N7）
- AC16: 超大读文件/搜索结果被截断时，返回内容标明已截断（对应 N4）
