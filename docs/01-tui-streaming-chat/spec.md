# MewCode 交互式流式对话 Spec

## 背景

要从零做终端 AI 助手 MewCode（类似 Claude Code）。仓库目前几乎为空，仅有项目说明。本轮只要「能在终端里多轮流式对话」，不包含 agent/工具能力。

## 目标

- 启动后进入交互式 TUI，可输入问题并看到模型流式回复
- 支持多轮对话，历史落盘；启动时可从历史中选择继续或新建
- 通过 YAML 配置 Anthropic / OpenAI 两类协议，配置可切换；请求以 SSE 流式返回
- Provider 层统一抽象，便于以后加后端
- 支持 Claude 扩展思考；TUI 默认折叠/摘要展示思考，正文正常流式
- 配置查找：优先项目配置，否则用户目录配置

## 功能需求

- F1: 用户可通过命令行启动 MewCode，进入交互式对话界面（TUI）
- F2: 用户可在界面中输入问题并提交；系统调用当前配置的大模型，以 SSE 流式返回，界面将正式回复逐字（流式）展示
- F3: 同一会话内支持多轮对话；后续回合携带本会话已有对话上下文，使模型能利用先前内容作答
- F4: 对话会话持久化到本地；进程退出后再启动，历史仍可访问
- F5: 启动时展示历史会话列表，用户可选择某一会话继续，或新建会话
- F6: 通过 YAML 配置管理 LLM 供应商；每条配置包含：`name`、`protocol`、`model`、`base_url`、`api_key`，以及可选的 `thinking`
- F7: 配置加载顺序为：优先项目内配置，若不存在则使用用户目录配置；能据此确定当前启用的供应商
- F8: `protocol` 至少支持 Anthropic Claude 与 OpenAI 两套协议；通过配置切换，无需改代码
- F9: 对上层面暴露统一的「流式对话」能力抽象；不同协议作为可替换实现，便于后续增加新后端
- F10: 当配置启用 `thinking` 且当前协议支持扩展思考时，请求启用该能力；界面默认不以全文展开思考，而以折叠/摘要形式展示（如「思考中…」或短摘要），正式回复仍正常流式展示
- F11: 当配置启用 `thinking` 但当前协议不支持时，仍可正常对话，并向用户给出明确告警（不中断为硬失败）

## 非功能需求

- N1: 实现语言为 TypeScript，可在常见桌面终端中作为命令行程序启动
- N2: 模型输出必须走流式（SSE），不得等完整生成结束后再一次性展示
- N3: 配置中的密钥等敏感信息仅用于本地请求认证，不得写入会话历史的可读正文中对外展示；示例配置不得提交真实密钥
- N4: 网络/认证/配置错误时，界面给出可读的中文错误信息，进程不应无提示崩溃
- N5: 本轮交付应能在本地用真实（或兼容）API 做一次端到端对话验证（与项目约定的终端/会话验收方式对齐）
- N6: 中文界面文案与中文代码注释（与项目语言约定一致）

## 不做的事

- 不实现 tool use、函数/工具调用编排
- 不实现读改写工作区文件、代码编辑、补丁应用、命令执行等 Agent 能力
- 不实现 MCP、插件市场、子 Agent 编排
- 不实现多模态（图片/语音）输入输出
- 不实现账号体系、云端同步会话；会话仅本地落盘
- 不实现图形界面（GUI）；仅终端 TUI
- 本轮不要求支持除 Anthropic Claude 与 OpenAI 协议以外的其他 Provider 实现（预留抽象即可）
- 不实现复杂权限/沙箱；本轮无工具故无命令执行沙箱需求

## 验收标准

- AC1: 在终端执行启动命令后，进入可交互的对话界面（非仅打印一行后退出）（对应 F1）
- AC2: 提交一句用户问题后，回复以流式方式逐渐出现在界面上，而非长时间空白后整段弹出（对应 F2）
- AC3: 同一会话中连续两轮提问，第二轮回复能体现对第一轮内容的依赖（可用约定测试话术观察）（对应 F3）
- AC4: 完成至少一轮对话后退出；再次启动仍能在历史中看到该会话及其关键内容（对应 F4）
- AC5: 启动后可见历史列表，并能完成「选中已有会话继续」与「新建会话」两种路径（对应 F5）
- AC6: 在项目配置与用户目录配置场景下，均能正确加载；存在项目配置时优先生效；字段 `name` / `protocol` / `model` / `base_url` / `api_key` / 可选 `thinking` 生效符合预期（对应 F6、F7）
- AC7: 分别配置 Anthropic 与 OpenAI 兼容协议时，均可完成至少一次流式对话（需可用的密钥与端点）。开发/验收默认优先使用 DeepSeek（`deepseek-v4-flash`，走 OpenAI 兼容协议）；Anthropic 在具备密钥时补充验证（对应 F8）
- AC8: 新增一种协议实现时，只需增加对应实现并挂到配置的 `protocol`，调用侧不依赖某一家私有细节（对应 F9）
- AC9: Claude 且 `thinking: true` 时，思考不以全文默认展开，界面有折叠/摘要态；正式回复仍流式展示（对应 F10）
- AC10: OpenAI（或不支持思考的协议）且 `thinking: true` 时，对话仍可进行，并出现明确告警文案（对应 F11）
- AC11: 故意使用错误 `api_key` 或错误 `base_url` 时，界面显示可读中文错误，而不是静默失败或未捕获崩溃（对应 N4）
