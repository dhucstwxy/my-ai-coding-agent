# 任务管理与持久化 Spec

## 背景

HTTP 服务已经能异步提交一次执行，结束后查询状态。运行记录写在服务数据目录的 JSON 文件里，事件是另一份流水。服务重启时，没跑完的任务会重新排队，已经写入对话的用户消息不会再写一遍。

这些记录还不适合按步骤查看历史。流水是文本增量，一段思考、一次工具调用和一段助手正文没有各自的完成记录。换存储之后，调用方仍用现在的标识提交、查询、取消和订阅事件。

对话正文在工作区里，终端会话在另一处。这两处都不是这次要搬的运行记录。

## 目标

- 一次执行，无论是一次性任务还是会话里的一轮，都是一个 Task，使用调用方现在已经拿到的那个唯一标识。
- 提交之后仍先返回，任务在后台执行。Task 的状态和已完成的 Step 写在服务自己的 SQLite 库里。服务重启后仍能列出 Task、读出 Step。
- Step 只有三类，并且只在这件事做完时记一条：一段思考、一次工具调用、一段助手正文。工具步骤带上成败和结果摘要。这次调用上的审批和警告附在该步骤上，不单独成步。
- 实时事件流保持原样，流式增量不写入 Step。另有查询可以读出某个 Task 已经完成的步骤。聊天页仍订阅事件流。
- 服务中断后的续跑与现在相同：未完成的 Task 重新排队，已经写入对话的用户消息不重复写入，模型重新打开这段对话继续。已经记下的 Step 保留，作为历史，不作为重放脚本，也不从某次工具调用的半中间接着执行。
- 已完成、失败或取消的 Task 不能从中间某一步再跑。
- 旧的 JSON 运行记录不导入。新库从空开始，那些文件留在磁盘上但不再被读取。工作区里的对话正文和终端会话文件保持原样。

## 功能需求

- F1: 一次性任务和会话里的每一轮，在被接受时就成为一个 Task，并使用调用方已经拿到的那个唯一标识。此时任务还没跑完，也可以被列出和查询。
- F2: Task 的状态写在服务自己的 SQLite 库里，包含调用方现在就能看到的那些状态信息。服务重启后，已结束和未结束的 Task 都还在，列出和查询仍使用原来的标识。
- F3: 一件事做完才记一条 Step，并且只记三类。一段思考结束时记一步，内容是这段思考的摘要；没有思考就不记。一次工具调用结束时记一步，包含工具名、对象、成败和结果摘要；这次调用发生过的审批和警告附在这一步上。一段助手正文结束时记一步，内容是这段正文；正文结束的时机是下一次工具调用开始，或这一轮结束。文本增量不记成 Step。
- F4: 不依附于某次工具调用的警告只出现在实时事件流里，不记成 Step。正在进行、尚未结束的思考、工具调用或正文也不记成 Step。
- F5: 可以按 Task 的标识读出它已经完成的 Step，顺序与完成顺序相同。任务仍在进行时只能读到已经完成的步骤；任务结束后步骤仍在。服务重启后这些步骤仍能读到。查不到该 Task 时，结果与查询一个不存在的任务相同。读取步骤使用与查询该任务相同的访问限制。
- F6: 实时事件流保持现在的内容，包括文本增量、工具活动、审批、警告和结束。聊天页仍订阅这条事件流，不改成步骤列表。
- F7: 提交、等待、列出、查询、取消、会话收发和审批选择的现有结果保持不变。一次性任务仍是六个内置工具并自动放行。会话这一轮仍有审批、技能、MCP 和钩子。排队、同一段对话正忙、访问限制也保持不变。
- F8: 服务中断后，未完成的 Task 按现在的条件重新排队，次数上限不变。已经写入对话的用户消息不重复写入。已经记下的 Step 保留。模型重新打开这段对话继续，不把 Step 当作脚本重放，也不从某次工具调用的半中间接着执行。
- F9: 已完成、失败或取消的 Task 不能从中间某一步再跑，也没有这样的入口。
- F10: 服务不读取、不导入旧的 JSON 运行记录。新库从空开始。工作区里的对话正文和终端会话文件保持原样，内容不写入这个库。

## 非功能需求

- N1: 一件事在实时事件流里显示为结束后，对应的 Step 已经写入库。服务在这之后中断，查询仍能读到这一步。
- N2: 尚在进行的思考、工具调用或正文如果被中断，不留下半条 Step。
- N3: 列出 Task 和读取 Step 不依赖执行器是否仍在运行。执行器不可用时，这两项查询与现在列出任务一样仍然可以完成。
- N4: 库不可用时，不接受新的任务，并说明原因。服务不改回去读旧的 JSON 运行记录。健康检查仍可访问。
- N5: 不使用步骤查询的调用方，看到的状态码、任务标识和事件流种类与现在相同。
- N6: Step 只保留摘要。它不包含工具的完整输出，也不包含配置密钥、MCP 环境变量的值或请求头的值。附在工具步骤上的审批与现在的审批展示使用同样的遮盖。
- N7: 这个库只有一份，放在服务自己的数据目录里。每个工作区不另存一份，服务也不打开终端的会话文件。
- N8: 新增的失败说明使用中文。

## 不做的事

- 不把工作区里的对话正文或终端会话文件搬进这个库，也不把两边的对话合并。
- 不导入、不读取、不删除旧的 JSON 运行记录。
- 不把文本增量、工具开始、尚未结束的审批各自记成 Step。不依附于某次工具调用的警告也不记成 Step。
- 不把 Step 当作可以重放的脚本，也不从某次工具调用的半中间继续执行。
- 不为已完成、失败或取消的 Task 提供从某一步再跑的入口。
- 不改变续跑的条件、次数上限，以及用户消息是否重复写入的现有结果。
- 不改变一次性任务和会话这一轮各自已有的工具、审批、技能、MCP 和钩子。
- 不改变提交、等待、列出、查询、取消、会话收发、审批选择、排队和访问限制的现有结果。
- 聊天页不改成步骤列表，也不新增取消、删除、重命名或分叉。
- 不保存工具的完整输出，也不另做一套审批遮盖规则。
- 不按工作区拆多个库，不给这个库做自动清理或保留期限。
- 不接入小组、子代理、斜杠命令、计划模式、权限档位切换或记忆。

## 验收标准

- AC1: 接受一次一次性任务和一次会话发送。两者都返回现在已有的那个标识。任务尚未结束时，用该标识可以列出并查询到它。（F1、F2）
- AC2: 一次执行里依次出现思考、工具调用和助手正文。步骤查询按这个顺序得到三步。文本增量不是步骤。工具步骤包含工具名、对象、成败和结果摘要；这次调用的审批和警告在这一步上。没有思考时，没有思考步骤。（F3）
- AC3: 工具调用尚未结束时，步骤查询里没有这一步。它在事件流里显示为结束后，步骤查询能读到它。不依附于工具调用的警告出现在事件流里，但不出现在步骤里。服务在该完成事件之后中断，重启后这一步仍在，且没有半条步骤。（F4、N1、N2）
- AC4: 用任务标识能读出已完成的步骤，进行中的任务只返回已经完成的。重启后步骤仍在。查询不存在的任务时，结果与查询一个不存在的任务相同。不带凭证时，读取步骤与查询该任务一样被拒绝。执行器停掉之后，列出任务和读取已保存的步骤仍然可以完成。（F5、N3）
- AC5: 实时事件流仍包含文本增量、工具活动、审批、警告和结束。聊天页仍订阅这条事件流，页面上没有步骤列表。（F6）
- AC6: 一次性任务仍自动放行，事件流里没有审批。会话这一轮遇到有副作用的工具仍会询问。排队、同一段对话正忙、取消和提交审批选择的结果与现在相同。不使用步骤查询的调用方看到的状态码、标识和事件流种类不变。（F7、N5）
- AC7: 一步已经出现在事件流之后，任务尚未结束时停掉服务。重启后这一步仍能读到，用户消息没有重复写入，该任务按现在的次数上限重新排队。已记下的步骤不会被当作脚本再执行一遍。（F8、N1）
- AC8: 已完成、失败或取消的任务没有从某一步继续的入口。再次查询时，原有步骤和结果不变。（F9）
- AC9: 在旧的 JSON 运行记录位置放一个过去的任务文件后启动服务，列表里没有它。工作区不新增数据库文件，对话正文和终端会话文件的内容不变。服务的数据目录里有这一份库。（F10、N7）
- AC10: 库不能打开或不能写入时，新的任务被拒绝，原因是中文。健康检查仍可访问。服务不靠读取旧 JSON 来接受这次任务。（N4、N8）
- AC11: 工具步骤的摘要里没有工具的完整输出，也没有配置密钥、MCP 环境变量的值或请求头的值。附在步骤上的审批与实时事件流里的审批使用同样的遮盖。（N6）
