# 任务管理与持久化 Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。

## 任务与步骤

- [x] 一次性任务和会话发送都返回现有任务标识。任务尚未结束时，用该标识可以列出并查询到它（验证：各提交一次，在结束前查询，对应 AC1）
- [x] 一次执行依次出现思考、工具调用和助手正文时，步骤查询按这个顺序得到三步。文本增量不是步骤。工具步骤含工具名、对象、成败和结果摘要。没有思考时没有思考步骤（验证：用会依次产生这三类事件的一轮查询步骤，对应 AC2）
- [x] 这次工具调用上的审批和警告出现在该工具步骤上。不依附于工具的警告只出现在事件流里（验证：对比同一次执行的事件流和步骤查询，对应 AC2、AC3）
- [x] 工具尚未结束时，步骤查询里没有这一步。事件流出现结束后，步骤查询能读到它。中断不留下半条步骤（验证：结束前查询一次，结束后再查询，对应 AC3、N2）
- [x] 进行中的任务只返回已完成的步骤。重启后这些步骤仍在。不存在的任务与查询该任务的结果相同。不带凭证时，读取步骤与查询该任务一样被拒绝。执行器停掉后，列出任务和读取已保存的步骤仍可完成（验证：重启前后各查一次，并在无凭证、无执行器时各请求一次，对应 AC4）
- [x] 实时事件流仍有文本增量、工具活动、审批、警告和结束。聊天页仍订阅这条事件流，页面上没有步骤列表，也不请求步骤接口（验证：看事件流和聊天页来源，对应 AC5）
- [x] 聊天页的已有对话列在左侧，主区域是输入和这一轮输出（验证：打开页面，列表在正文左侧，对应计划中的聊天页）

## 原有行为

- [x] 一次性任务仍自动放行，事件流里没有审批。会话这一轮遇到有副作用的工具仍会询问。排队、同一段对话正忙、取消和提交审批选择的结果与现在相同（验证：各走一次现有路径，对应 AC6）
- [x] 一步已经出现在事件流之后、任务尚未结束时停掉服务。重启后这一步仍能读到，用户消息没有重复写入，该任务按现在的次数上限重新排队。已记下的步骤不会再执行一遍（验证：中断并重启后看步骤、对话文件和任务状态，对应 AC7）
- [x] 已完成、失败或取消的任务没有从某一步继续的入口。再次查询时，步骤和结果不变（验证：对已结束任务再次查询，对应 AC8）

## 库

- [x] 在旧的 JSON 运行记录位置放一个过去的任务文件后启动，列表里没有它。工作区不新增数据库文件，对话正文和终端会话文件的内容不变。服务数据目录里有一份 `tasks.sqlite`（验证：启动后看列表和这三个位置，对应 AC9）
- [x] 库不能打开或不能写入时，新任务被拒绝，原因含「任务库不可用」。健康检查仍可访问。服务不靠读取旧 JSON 来接受这次任务（验证：让库路径不可用后提交一次并访问健康检查，对应 AC10）
- [x] 工具步骤的摘要里没有工具的完整输出，也没有配置密钥、MCP 环境变量的值或请求头的值。步骤上的审批与事件流里的审批使用同样的遮盖（验证：用含密钥的参数触发一次工具步骤，对比两处文本，对应 AC11）

## 端到端场景

- [ ] 场景 1：启动服务，打开聊天页。左侧是对话列表。在一段对话里发送会改文件的请求。询问出现时文件还没改。选择仅本次放行后，文件发生变化，事件流继续。结束后用该任务标识读到的步骤里，有这次工具调用和随后的助手正文，且没有文本增量那种碎步骤（验证：浏览器观察左侧列表、按钮和文件，再请求步骤接口）
- [x] 场景 2：一步已经出现在事件流之后停掉服务再启动。该步骤仍能读到，同一句用户消息没有在对话里出现第二次。接着提交一次一次性任务，事件流里没有审批，步骤查询对不存在的标识被拒绝（验证：重启前后各查一次步骤，并提交一次一次性任务）
