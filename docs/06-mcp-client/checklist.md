# MewCode MCP 客户端 Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。  
> 不依赖真实远程服务的条目，用临时假 Server 驱动。假 Server 跑完即删。需要界面的条目在本机终端观察。

## 实现完整性

- [ ] 没有 Server 或列表为空时可以启动，模型仍能看到原来的六个内置工具（验证：不写 `mcp_servers` 启动一次，工具列表里有读、写、改、命令、查找、搜索）（AC1）
- [ ] 能握手的本地 Server，工具名是「服务器名__工具原名」，说明和参数结构与远端一致。与内置工具同名的那个不注册，并有可读警告（验证：假 Server 提供 `echo` 和 `read_file`，只出现带前缀的 `echo`）（AC2）
- [ ] 用户级和项目级同名 Server 时，用的是项目级整段配置，不是两边字段拼起来。供应商仍按原来的规则读取（验证：用户级写命令 A，项目级同名只写命令 B，实际启动的是 B；现有供应商配置仍能加载）（AC3）
- [ ] 服务器名不合法、缺少命令或缺少地址时跳过并警告。同一次启动里其他合法 Server 仍能注册工具（验证：一份配置里同时放非法项和合法项）（AC4）
- [ ] 环境变量和请求头里的 `${变量名}` 会展开。变量不存在时该 Server 不连接。警告里有变量名，没有已展开的密钥或请求头内容（验证：一个存在的变量、一个不存在的变量；警告文本里搜不到存在变量的值）（AC5）
- [ ] 写在命令、参数或远程地址里的 `${变量名}` 保持原文（验证：命令字符串里放一个已存在的变量，实际执行的命令仍含 `${`）（AC6）
- [ ] 本地子进程按行收发。标准错误里有内容时，仍能列出工具并完成一次调用（验证：假进程向标准错误写一行，再正常应答）（AC7）
- [ ] 远程传输对同一次请求，既能收下整份 JSON，也能把流式事件拼成同一次结果（验证：本地 HTTP 假服务分别返回这两种正文）（AC8）
- [ ] 同一 Server 上两条未完成请求的回包按编号各自返回。没有编号的通知不会让调用方一直等。对不上的编号不会让进程退出（验证：故意把两条回包对调送回；再送一条通知和一条陌生编号）（AC9）
- [ ] 握手失败、协议版本不一致，或列出工具失败时，该 Server 没有工具。另一个成功 Server 的工具仍在，程序仍能进入对话（验证：三个坏 Server 加一个好 Server）（AC10）
- [ ] 列出工具有多页时，后面几页也会注册（验证：第一页带下一页标记，第二页再给一个工具，两个都能被调用）（AC11）
- [ ] 计划模式看不到远端工具。执行模式看得到，并且它们不会和其他有副作用的工具并发执行（验证：计划模式的工具列表里没有带 `__` 的名字；执行模式里有。连续两个副作用调用时，第二个开始时第一个已经结束）（AC12）
- [ ] 没有规则时，默认档询问，严格档拒绝，放行档直接调用。精确规则不因参数键的顺序不同而错过。本会话或永久放行后，换一组参数会重新判断（验证：同一工具用两种键顺序各走一次闸门；放行一次后再换参数）（AC13）
- [ ] 放行档下，远端工具不会因为参数像危险命令，或参数里有项目外路径，就被黑名单或路径沙箱拒绝（验证：放行档调用参数为 `rm -rf /` 和 `C:\Windows\win.ini` 的远端工具，拒绝原因不是黑名单或越界）（AC14）
- [ ] 调用成功时能看到文本结果。远端报错、调用超时或子进程已退出时，得到失败说明，循环不因此结束。之后同一 Server 仍失败，不自动重连。其他 Server 仍可调用（验证：成功、`isError`、杀掉子进程后再调一次，并紧接着调另一个 Server）（AC15）
- [ ] 握手超过等待上限时放弃该 Server，界面能看到中文警告，对话仍然可以开始（验证：假 Server 在握手时不回复，等待结束后仍进入会话列表，警告是中文）（AC16）

## 集成

- [ ] 远端工具走现有工具中心和权限闸门，不是另一条调用路径（验证：放行档下一次成功调用会留下普通的工具结果；默认档会先出现四个确认选项）
- [ ] 启动警告和权限警告出现在同一处。某个 Server 失败不会清掉已经注册的其他远端工具（验证：同时配置一个好 Server 和一个坏 Server，界面上两者都能看出来）
- [ ] 进程退出时本地子进程被关掉。有会话标识的远程连接会发出删除会话（验证：退出后假子进程不再存在；HTTP 假服务收到删除请求）

## 编译与测试

- [ ] `npm run typecheck` 退出码 0
- [ ] `npm start` 在未配置 Server 时仍能进入终端界面
- [ ] 未配置 lint，本项记为跳过

## 端到端场景

- [ ] 场景 1（无模型）：临时项目配置里放一个会应答的本地 Server 和一个缺环境变量的 Server。启动后只有前者的工具被注册，警告里能看到缺失的变量名，看不到其他密钥。调用一次能拿到文本（AC2、AC5、AC7）
- [ ] 场景 2（无模型）：放行档调用这个远端工具，参数写成危险命令的样子，调用仍然发出并返回文本，而不是被黑名单拦住。默认档下同一次调用会先询问（AC13、AC14）
- [ ] 场景 3（终端界面）：不配 Server 时，`npm start` 能进会话列表。配上一个握手时故意不回复的 Server 后，等待结束后仍能进列表，并看到中文警告（AC1、AC16）
- [ ] 场景 4（有本地假 Server 时）：执行模式能让模型看到带前缀的工具名；`/plan` 之后这份名单里没有它。没有密钥或假 Server 时，本条只记录跳过（AC12）
