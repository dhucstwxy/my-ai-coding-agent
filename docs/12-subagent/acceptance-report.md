## 通过

- [x] 工具名单里始终有 `agent`。计划模式和 Skill 白名单收窄后仍在，写文件不在。缺类型或类型不对时调用失败，任务表为空
- [x] 定义式系统提示只有角色正文，任务说明是第一条用户消息。父会话只有最终答复，没有子任务的工具往来
- [x] Fork 即使要求前台也立即转入后台。首次请求的系统提示、工具列表和快照前缀与父请求一致，父对话后来新增的消息不进入 Fork
- [x] 显式后台、运行超时、按 `b` 都会在结束前返回任务标识。确认框打开时 `b` 不转入后台。权限确认的等待不计入时限。同时只有一个前台，两个后台可以并行
- [x] 空闲时送回标识、最终答复和用量，并自动再跑一轮，正文只出现一次。父对话正忙时结果不插进当前工具调用，本轮结束后只出现一次。离开会话后运行记录消失
- [x] Esc 取消前台子任务，结果不是转入后台。没有前台子任务时 `b` 不转入后台
- [x] 前台询问确认前没有副作用。后台需要询问时不弹框，拒绝说明回到子任务。本会话放行互不影响。永久放行写入后，其它会话不用再问
- [x] 项目角色覆盖用户和内置。提醒里有名字和用途、没有正文，位置在 Hook 注入之后、工作区路径之前。坏文件只警告。同层重名、未知工具都会让进程退出码为 1，错误含角色名，未知工具时再含工具名，且没有调用模型
- [x] 没写模型时用父会话模型。未知模型这次委派失败，不建任务。轮次上限的答复含原因和已有正文
- [x] 定义式去掉委派工具。白名单为空则没有工具。黑名单优先。Fork 再调用委派工具时，闸门调用次数为 0，子任务继续
- [x] 子任务会触发回合、消息、压缩。不触发会话开始和结束。父会话注入不出现，子任务自己的注入会出现，结束后被清掉。压缩不改父会话存档
- [x] Hook 按名字启动的任务只把最终答复写进日志，不写父会话。名字对不上只记日志。子会话里再触发时不调用启动函数
- [x] `/help` 不刷新角色目录。进入对话循环前会刷新。子任务用量不改变父会话上下文锚点

## 端到端

- [x] 场景 1：三级同名角色里，提醒和定义式运行用的是项目级用途和正文。父会话只有最终答复
