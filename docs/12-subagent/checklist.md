# 子 Agent Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。

## 实现完整性

- [x] 主 Agent 的工具列表里始终有委派工具，计划模式和 Skill 白名单收窄后仍在。类型缺失或不是定义式、Fork 式时，调用失败并说明原因，没有子 Agent 开始（验证：看工具名列表；用缺类型的调用看结果和任务数）（AC1）
- [x] 定义式从空白对话开始，系统提示只有角色正文。子 Agent 不再调工具后，主 Agent 只拿到最终答复。父会话存档里没有子 Agent 的中间消息。没有正文或因错误停下时，答复说明情况和已有正文（验证：打桩两轮，读父会话文件和工具结果）（AC2）
- [x] Fork 的首次请求在新任务之前，系统提示和工具列表与父对话最近一次模型请求相同，新任务在其后。父对话之后新增的消息不进入这个 Fork（验证：对比两次请求的前缀）（AC3）
- [x] 定义式指定后台、前台实际运行满 60 秒，或按 `b` 时，调用在结束前返回，内容含已在后台和任务标识，不含最终答复。等权限确认的时间不计入 60 秒。Fork 即使要求前台也走后台。启动前失败不建立任务。同时只有一个前台。两个后台可以并行，且不挡住父对话的下一轮（验证：打桩耗时与返回文本；同时看两个任务的状态）（AC4）
- [x] 非 Hook 的后台任务结束后，父会话出现带标识、最终答复和用量的消息。主 Agent 空闲时自动再跑一轮。正忙时结果在当前轮次结束后才出现，不插进正在进行的工具调用。界面能看到进行中任务的标识和状态。离开会话或进程退出后记录消失（验证：空闲和正忙各跑一次，读会话文件和界面状态）（AC5）
- [x] 前台子 Agent 运行时按 Esc，子 Agent 停止，委派按取消结束，不转入后台。没有前台子 Agent 时按 `b` 不转入后台。权限确认框打开时按 `b` 不转入后台。确认期间按 Esc，这次询问被拒绝，前台子 Agent 取消（验证：模拟按键，看任务状态和工具是否执行）（AC6）
- [x] 子 Agent 使用角色声明的档位；没写则用启动时父会话的档位。前台需要询问时会问用户，确认前没有副作用。后台需要询问时不出现确认框，拒绝说明交给子 Agent。两边的本会话放行互不影响。永久放行写入本地规则后父会话能命中。子 Agent 的用量不计入父会话上下文（验证：打桩确认次数、放行记录和用量）（AC7）
- [x] 合法角色能被加载。缺名字、名字不合法或正文为空则跳过并给出原因，其它角色仍在。项目覆盖用户，用户覆盖内置。环境提醒里有名字和用途，没有正文，位置在 Hook 注入之后、工作区路径之前。同一层级重名，或白名单、黑名单点到不存在的工具时，进程退出码非 0，错误含角色名，未知工具时再含工具名，没有进行中的子 Agent。损坏文件被跳过后其余仍可用（验证：三份临时角色对照提醒文本；坏文件看退出码）（AC8）
- [x] 没写模型时用父会话当时的模型。写了配置里没有的名字，这次委派失败，不启动子 Agent。没写最大轮次时与主对话相同。写成 0 或负数，或权限档位不在三档之内，该角色被跳过并给出原因。到达轮次上限时，答复含停下的原因和已有助手正文（验证：打桩请求里的模型名和停止原因）（AC9）
- [x] 定义式的工具列表没有委派工具。白名单会收窄；白名单为空则没有可用工具。黑名单去掉对应工具；两边都写时以黑名单为准。Fork 的工具列表与父请求相同。Fork 再调用委派工具时失败并说明不能再委派，子 Agent 继续，且不进入权限闸门。后台不改变工具列表。留在列表里的写文件和执行命令在后台可以执行。被角色排除的工具在执行时失败。加载 Skill 的工具可以被留下，也可以被关掉（验证：对比发给模型的工具名和闸门调用次数）（AC10）
- [x] 子 Agent 的回合、消息、工具和压缩会触发 Hook。会话开始和会话结束不触发。注入和只跑一次只出现在这个子 Agent 的后续请求里。父会话已有的注入不出现在子 Agent 的请求里。子 Agent 结束时它自己的注入消失。压缩不改父会话存档（验证：打桩事件列表，并读两份会话）（AC11）
- [x] Hook 按名字启动的定义式子 Agent 直接在后台。最终答复出现在日志里，不在父会话里，主 Agent 不因此再跑一轮。名字对不上时日志有失败原因，父任务继续。子 Agent 自己的会话上再触发子代理动作时，只记不再启动，不建立新任务。子 Agent 中途失败只结束它自己（验证：读日志、父会话文件和任务数）（AC12）

## 集成

- [x] 再委派和角色列表之外的工具在权限询问之前被拒绝。闸门不被调用，工具没有副作用（验证：打桩 `check` 次数为 0）（AC10）
- [x] 本地命令不刷新角色目录。进入对话循环前会刷新。刷新发现同层重名时进程退出，模型没有被调用（验证：`/help` 与普通文本各一次）（AC8）
- [x] 后台结果写成父会话的用户消息后只出现一次。随后的一轮不再把同一段正文追加第二次（验证：读会话文件里的出现次数）（AC5）
- [x] 子循环结束不更新长期记忆。父会话的上下文用量不包含子 Agent 的输入和输出（验证：记忆文件未改，父会话用量前后对比）（AC7）

## 端到端场景

- [x] 场景 1：项目、用户、内置各有一个同名角色。进入对话后，提醒里看到的是项目级的名字和用途，看不到正文。主 Agent 用定义式把任务交给它，父会话里只有最终答复，没有子 Agent 的工具往来
- [x] 场景 2：定义式指定后台。调用立刻返回任务标识。结束后父会话出现带标识、最终答复和用量的消息，并自动再跑一轮。另一次 Fork 即使要求前台也在后台，且首次请求的系统提示和工具列表与父请求相同
- [x] 场景 3：前台子 Agent 要执行命令时出现权限确认，确认前命令没有执行。按 `b` 转入后台后，下一次需要询问的调用不再出现确认框。Hook 按角色名启动的任务只把最终答复写进日志
