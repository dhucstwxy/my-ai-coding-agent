# 子 Agent Spec

## 背景

MewCode 已经能在一条对话里调工具、按权限档询问或拒绝，也能把重复操作做成 Skill。Skill 的独立模式会另开一段对话，但那是按固定文档跑完再把摘要送回，不是主 Agent 临时把一个子任务交出去。Hook 里的子代理动作也还只记一条日志。探索、修改、执行若都堆在同一条上下文里，中间的工具往来会一直占着窗口。

## 目标

- 主 Agent 用同一个委派工具交出子任务。这个工具一直都在，用类型区分定义式和 Fork 式
- 定义式从空白对话开始，整个生命周期使用该角色的正文作为系统提示。Fork 式带上父对话当时的系统提示、工具列表和已有历史，新的任务说明加在历史之后，使首次请求能沿用父请求已经形成的缓存。Fork 不另换一套角色正文
- 每个子 Agent 的消息、本会话权限放行和用量各自记账，也和父会话分开。模型访问、Hook 规则、工作区文件共用。父会话里已经读过的文件内容不会被塞进子 Agent 的上下文。这一步不另做一份文件读取缓存
- 定义式默认停在这次委派上，直到子 Agent 不再调工具。主 Agent 拿到的工具结果只有最终答复：停止调工具时的那段助手正文。因轮次上限或错误停下时，送回的文字包含停下的原因，以及已经写出的助手正文
- 定义式可以在调用时指定后台。前台实际运行满 60 秒，或用户在前台子 Agent 运行期间按 `b`，也转入后台，子 Agent 继续跑。等权限确认的时间不计入这 60 秒。Fork 一律后台，即使调用时要求前台也一样。转入后台时，这次委派先返回已在后台
- 后台任务结束后，把最终答复写入主对话。主 Agent 正空闲就自动再跑一轮；正忙则排到当前这轮结束之后，不插进正在进行的工具调用中间。Hook 启动的子 Agent 不走这条通知，最终答复只记日志
- 前台子 Agent 运行时按 Esc，子 Agent 停止，这次委派按取消结束。Esc 不把任务转入后台
- 每个子 Agent 有自己的权限档位和本会话放行，与父会话互不影响。角色写了档位就用它，没写就用启动时父会话的档位。前台仍会询问。后台里需要询问的调用直接拒绝，拒绝说明交给子 Agent。永久放行仍写入本地规则
- 角色是一份带元信息的文档。元信息有名字、用途、工具白名单、工具黑名单、模型、最大轮次、权限档位。正文是系统提示。存放在项目、用户、内置三处，同名时项目覆盖用户，用户覆盖内置。每次委派前重新读取。没写模型就用父会话当前模型；写了就必须是配置里已有的名字，否则这次委派失败。没写最大轮次就与主对话的轮次上限相同
- 定义式的工具列表里没有委派工具。Fork 的工具列表与父请求相同，再调用委派工具时拒绝执行。角色的白名单和黑名单在此之上再收窄。后台不改变发给模型的工具列表，只在执行时拒绝角色不允许的调用。写文件和执行命令可以在后台执行。加载 Skill 的工具不在全局禁止里
- 子 Agent 用自己的会话标识触发 Hook。回合、消息、工具和压缩会触发。注入的提示词和只跑一次只留在这个子 Agent 身上。不给父会话再发一次会话开始，父会话里已有的注入也不会出现在子 Agent 里
- 后台任务记下状态、最终答复和用量，留在当前进程里。离开会话或进程退出后不再保留
- 不做工作区副本隔离、多 Agent 编队，也不做后台任务的跨会话持久化。这一步不附带内置角色样板，也不提供把已经在后台的任务中途取消的操作

## 功能需求

### 委派

- F1: 委派工具始终提供给主 Agent，不随模式或角色出现或消失。调用时用类型选择定义式或 Fork 式。类型缺失或不是这两者，这次调用失败并说明原因，不启动子 Agent。
- F2: 定义式必须带角色名和任务说明。角色名对不上已加载角色，或任务说明为空，这次调用失败并说明原因，不启动子 Agent。对话从空白开始。系统提示在整个运行期间都是该角色的正文，不附带主对话那份固定系统提示。任务说明是第一条用户消息。
- F3: Fork 式必须带任务说明，不使用角色正文。它复制委派发生时父对话最近一次模型请求的系统提示、工具列表和消息。任务说明接在这些消息之后。此后父对话新增的内容不再进入这个 Fork。
- F4: 定义式默认停在这次调用上，直到子 Agent 不再发起工具调用。交回主 Agent 的工具结果只有最终答复。子 Agent 的中间消息不写入父会话存档。
- F5: 最终答复是子 Agent 停止发起工具调用时的那段助手正文。因轮次上限或错误停下时，答复里包含停下的原因，以及已经写出的助手正文。没有助手正文时，答复说明已经结束但没有留下正文。
- F6: 定义式可以在调用时要求后台。前台累计实际运行满 60 秒，或用户在前台子 Agent 运行期间按 `b`，也转入后台，子 Agent 继续跑。等权限确认的时间不计入这 60 秒。Fork 一律后台。转入后台时，这次调用立即返回，说明已在后台，并带上该任务的标识。最终答复不在这次返回里。
- F7: 要求后台但角色名、任务说明或模型在启动前就失败时，不建立后台任务，调用直接返回失败原因。
- F8: 同一时刻最多一个前台子 Agent。后台任务可以彼此并行，也可以和主 Agent 之后的轮次并行。
- F9: 后台任务结束且不是由 Hook 启动时，把最终答复写入父会话，标明任务标识。主 Agent 没有正在进行的轮次时，写入后自动再跑一轮。正在进行轮次时先排队，当前轮次结束后按完成顺序写入，再自动跑一轮；这一轮能看到排队期间写完的全部结果。不插进正在进行的工具调用中间。
- F10: 前台子 Agent 运行期间按 Esc，子 Agent 停止，这次委派按取消结束，不转入后台。主 Agent 正忙于自己的工具、并没有前台子 Agent 时，按 `b` 不产生转入后台的效果。

### 权限

- F11: 每个子 Agent 有自己的权限档位和本会话放行记录，与父会话以及其他子 Agent 互不影响。角色写了档位就用它，没写就用启动那一刻父会话的档位。档位只有严格、默认、放行三档。
- F12: 前台运行时，需要询问的调用仍问用户，答完后子 Agent 继续。后台运行时，需要询问的调用直接拒绝，拒绝说明交给子 Agent，子 Agent 可以改做法或结束。永久放行仍写入本地规则，之后父会话也能命中。本会话放行只留在这个子 Agent 上。
- F13: 权限确认框打开时，`b` 不转入后台。确认期间按 Esc，拒绝这次询问并取消前台子 Agent。

### 角色

- F14: 一个角色是一份文档。元信息包含名字、可选的用途说明、可选的工具白名单、可选的工具黑名单、可选的模型、可选的最大轮次、可选的权限档位。正文是系统提示。
- F15: 名字只含小写字母、数字和连字符，登记时忽略大小写。缺名字、名字不合法或正文为空，这个角色跳过，并给出原因。同一层级里名字重复，重新读取失败，进程退出，错误指出这个名字。
- F16: 角色来自项目、用户、内置。同名时项目覆盖用户，用户覆盖内置。文件不存在视为这一级没有角色。每次委派前重新读取。单个文件损坏则跳过该角色，其余仍可用。白名单或黑名单里的工具在重新读取时不存在，进程退出，错误同时含角色名和工具名。
- F17: 重新读取成功后，主 Agent 在后续环境提醒里看到已加载角色的名字和用途说明，看不到正文。没有用途说明时只看到名字。
- F18: 委派时才解析模型。没写就用父会话当时的模型。写了但配置里没有这个名字，这次委派失败，不启动子 Agent。最大轮次没写则与主对话的轮次上限相同。写了则必须是正整数，否则这个角色在读取时跳过并给出原因。权限档位写了但不是三档之一，同样跳过。

### 工具

- F19: 定义式发给模型的工具列表里没有委派工具。在此之上，写了白名单就只保留名单中的工具；白名单存在但为空，则没有可用工具。黑名单从结果中去掉对应工具。同一工具又在白名单又在黑名单里，以黑名单为准。没写白名单表示不收窄，没写黑名单表示不额外去掉。加载 Skill 的工具不在全局禁止里，角色仍可用白名单或黑名单关掉它。
- F20: Fork 发给模型的工具列表与父请求相同，其中可以包含委派工具。子 Agent 再调用委派工具时，调用失败，说明不能再往下委派，子 Agent 继续运行。定义式因为列表里没有这个工具，不会发起这种调用。
- F21: 后台不改变已经决定的工具列表。执行时，角色过滤后不允许的工具直接失败，说明交回子 Agent。写文件和执行命令若留在列表里，后台可以执行。

### Hook 与记账

- F22: 子 Agent 使用自己的会话标识触发 Hook。回合、消息、工具和压缩会触发。不触发会话开始和会话结束。注入的提示词和只跑一次只留在这个标识上。父会话已有的注入不会出现在子 Agent 的请求里。子 Agent 结束时清掉它自己的注入和只跑一次。它的上下文压缩只处理它自己的消息，不改父会话存档。
- F23: Hook 的子代理动作按名字启动定义式子 Agent，直接处于后台，不占用前台，也不适用按 `b` 或 60 秒转入。用户消息使用该角色的用途说明；没有用途说明时，用户消息要求它按自己的系统提示执行。最终答复只记日志，不写入父会话，也不让主 Agent 再跑一轮。名字对不上已加载角色时，只记失败原因，不打断当前任务。
- F24: 每份后台任务在当前进程内有唯一标识，并记下类型、状态、最终答复和用量。状态为进行中、已完成、已失败或已取消。用量是这个子 Agent 自己各次模型请求的输入与输出，不计入父会话的上下文。聊天界面在有进行中的任务时展示标识和状态。完成并送回主对话的消息里带上标识、最终答复和用量。离开会话或进程退出后，这些记录消失。

## 非功能需求

- N1: 角色重新读取失败时，进程退出码非 0，错误信息含角色名；白名单或黑名单点到不存在的工具时，同时含工具名。退出前没有留下进行中的子 Agent，也不进入半截委派。
- N2: 单个子 Agent 的模型错误、工具失败或到达轮次上限，只结束这个子 Agent。父对话继续。Hook 启动失败或子 Agent 中途失败，只记日志，不结束父对话当前任务。
- N3: 子 Agent 的中间消息不出现在父会话存档里。父会话里能看到的，只有前台时的那条最终答复，或后台交接说明，以及结束后送回的那条结果。
- N4: 子 Agent 的本会话放行不能让父会话跳过询问，父会话的本会话放行也不能让子 Agent 跳过询问。子 Agent 的用量不计入父会话的上下文。
- N5: Fork 首次请求里，新任务之前的系统提示和工具列表与父对话最近一次模型请求相同。新任务位于这些内容之后。
- N6: 转入后台的那次调用在子 Agent 结束之前返回。返回内容里还没有最终答复。多个后台任务不互相阻塞，也不阻塞父对话的下一轮。
- N7: 后台里需要询问的调用不出现权限确认。前台需要询问时，用户确认前工具没有副作用。
- N8: 角色校验、工具列表、前台结果与后台交接、权限隔离、Hook 只记日志，不依赖真实模型就能检查。按 `b`、Esc 和进行中任务的界面展示，可以用模拟输入检查，不必打开真实终端。

## 不做的事

- 不做工作区副本隔离。子 Agent 与父会话读写同一批文件
- 不做多 Agent 编队、任务看板，也不让角色之间互相派活。只有主 Agent 和 Hook 能启动子 Agent
- 不做后台任务的跨会话持久化。离开会话或进程退出后，任务记录、最终答复和用量都不保留，重启后也不恢复
- 不提供把已经在后台的任务中途取消的操作。Esc 只取消还在前台的子 Agent
- 不附带内置角色样板。内置这一级可以是空的
- 不扫描插件目录，也不读取插件级角色
- 不把 haiku、sonnet、opus 当作模型别名。模型名只认配置里已有的名字
- 不另做一份文件读取缓存，也不把父会话已经读过的文件内容塞进子 Agent
- 不把 Hook 启动的子 Agent 的最终答复写入父会话，也不为此再跑一轮主 Agent
- 不让子 Agent 再成功启动下一层子 Agent。定义式的工具列表里没有委派工具；Fork 调用委派工具时直接失败
- 不在后台改写已经决定的工具列表，也不在后台弹出权限确认

## 验收标准

- AC1（F1）：主 Agent 的工具列表里始终有委派工具。类型缺失，或不是定义式、Fork 式时，调用失败并说明原因，没有子 Agent 开始。
- AC2（F2、F4、F5、N3）：定义式带合法角色和任务时，从空白对话开始，系统提示是角色正文，不含主对话那份固定系统提示。子 Agent 不再调工具后，主 Agent 的工具结果只有最终答复。父会话存档里没有子 Agent 的中间消息。没有助手正文时，答复说明已经结束但没有留下正文。因错误停下时，工具结果含原因和已有助手正文。
- AC3（F3、N5）：Fork 的首次请求在新任务之前，系统提示和工具列表与父对话最近一次模型请求相同，历史是当时的副本，新任务在其后。父对话之后新增的消息不进入这个 Fork。
- AC4（F6、F7、F8、N6）：定义式指定后台、前台实际运行满 60 秒，或按 `b` 时，调用在子 Agent 结束前返回，内容含已在后台和任务标识，不含最终答复。等权限确认的时间不计入 60 秒。Fork 即使要求前台也走后台。启动前失败不建立后台任务。同时只有一个前台子 Agent。两个后台任务可以并行，且不挡住父对话的下一轮。
- AC5（F9、F24）：非 Hook 的后台任务结束后，父会话出现带标识、最终答复和用量的消息。主 Agent 空闲时自动再跑一轮。主 Agent 正忙时，结果在当前轮次结束后才出现，不插进正在进行的工具调用。进行中的任务在界面上能看到标识和状态。离开会话或进程退出后，这些记录消失。
- AC6（F10、F13）：前台子 Agent 运行时按 Esc，子 Agent 停止，委派按取消结束，不转入后台。没有前台子 Agent 时按 `b` 不转入后台。权限确认框打开时按 `b` 不转入后台。确认期间按 Esc，这次询问被拒绝，前台子 Agent 取消。
- AC7（F11、F12、N4、N7）：子 Agent 使用角色声明的档位；没写则用启动时父会话的档位。前台需要询问时会问用户，确认前没有副作用。后台需要询问时不出现确认框，拒绝说明交给子 Agent。父会话的本会话放行不能让子 Agent 跳过询问，反过来也不行。永久放行写入本地规则后，父会话能命中。子 Agent 的用量不计入父会话上下文。
- AC8（F14–F17、N1）：合法角色能被加载。缺名字、名字不合法或正文为空则跳过并给出原因，其它角色仍在。项目覆盖用户，用户覆盖内置。环境提醒里有名字和用途，没有正文。同一层级重名时进程退出码非 0，错误含该名字。白名单或黑名单点到不存在的工具时，退出码非 0，错误含角色名和工具名，没有进行中的子 Agent。每次委派前重新读取；损坏文件被跳过后，其余角色仍可用。
- AC9（F5、F18）：没写模型时用父会话当时的模型。写了配置里没有的名字，这次委派失败，不启动子 Agent。没写最大轮次时与主对话相同。写成 0 或负数的角色被跳过并给出原因。非法权限档位的角色同样被跳过。到达轮次上限时，答复含停下的原因和已有助手正文。
- AC10（F19–F21）：定义式的工具列表没有委派工具。白名单会收窄；白名单存在但为空，则没有可用工具。黑名单去掉对应工具；两边都写时以黑名单为准。Fork 的工具列表与父请求相同。Fork 再调用委派工具时失败，并说明不能再委派，子 Agent 继续。后台不改变工具列表。留在列表里的写文件和执行命令在后台可以执行。被角色排除的工具在执行时失败，说明交回子 Agent。加载 Skill 的工具可以被角色留下，也可以被角色关掉。
- AC11（F22）：子 Agent 的回合、消息、工具和压缩会触发 Hook。会话开始和会话结束不触发。注入和只跑一次只出现在这个子 Agent 的后续请求里，不出现在父会话。父会话已有的注入不出现在子 Agent 的请求里。子 Agent 结束时，它自己的注入消失。子 Agent 的压缩不改父会话存档。
- AC12（F23、N2）：Hook 按名字启动的定义式子 Agent 直接在后台。最终答复出现在日志里，不在父会话里，主 Agent 不因此再跑一轮。名字对不上时，日志有失败原因，父任务继续。子 Agent 中途失败只结束它自己，父任务继续。
- AC13（N8）：角色校验、工具列表、前台结果与后台交接、权限隔离、Hook 只记日志，不调用真实模型就能检查。按 `b`、Esc 和进行中任务的展示可以用模拟输入检查。
