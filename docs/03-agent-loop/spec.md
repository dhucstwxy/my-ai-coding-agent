# MewCode Agent Loop Spec

## 背景

第二章已有六工具与「一次只执行第一个工具 + 再要一次纯文本」的半自动链路。模型仍一步一停，需用户反复催。本轮要装上 Agent Loop，让其在单次用户任务内自主多轮「推理 → 调工具 → 看结果 → 再调整」。

## 目标

- ReAct 循环：反复调 LLM、执行工具、结果回写，直到模型不再要工具或触达停止条件
- 停止条件覆盖：模型自然结束、迭代上限（默认 20）、用户取消、连续 2 次未知工具、流出错
- 异步事件流（文本、工具调用、工具结果、Token 用量、进度），Agent 与界面解耦
- 流式双路：实时推文本给界面 + 攒完整响应供循环判断
- 多工具调用：只读可并发，写/改/命令串行（同批先并发只读，再串行副作用）
- Plan Mode：会话级 `/plan` 仅 `read_file` / `glob_files` / `grep_search`；`/do` 恢复全工具
- 取消：忙碌时 Esc 取消循环；空闲时 Esc 返回会话列表
- 本轮不做：权限系统、上下文压缩、用户交互式确认

## 功能需求

- F1: 用户一次提问后，系统进入 Agent 循环：反复「调用模型 →（若有）执行工具 → 将工具结果写回对话 → 再调用模型」，无需用户每步催促
- F2: 当某次模型回复不再包含工具调用时，循环正常结束，并将最终文本展示给用户
- F3: 单次用户任务内，调用模型的次数不超过默认上限 20；触顶时停止循环并向用户说明因达到迭代上限而停止
- F4: 用户可取消正在进行的循环：对话忙碌时按 Esc 取消本轮循环；空闲时按 Esc 返回会话列表
- F5: 若模型连续 2 次请求未知工具名（注册表中不存在），停止循环并向用户说明原因
- F6: 模型流式响应或工具执行链路出现不可恢复错误时，停止循环，并以可读方式展示错误（进程不崩溃）
- F7: 循环过程通过异步事件流向外通知，至少包括：文本增量、工具调用开始/结束、工具结果、Token 用量（若上游提供）、进度（如当前迭代序号/上限）
- F8: 界面仅订阅事件流展示，不直接嵌入循环内部控制逻辑（Agent 与界面解耦）
- F9: 流式收集双路并行：一路实时把文本增量推给界面；一路在同一次模型响应内攒出完整结果（含工具调用列表），供循环决定下一步
- F10: 同一次模型回复若包含多个工具调用：只读工具（`read_file`、`glob_files`、`grep_search`）可并发执行；有副作用工具（`write_file`、`edit_file`、`run_command`）串行执行；同批先完成只读并发，再按序执行副作用
- F11: 每个工具结果（成功或结构化失败）都写回对话历史，供后续模型轮次使用；会话落盘行为与现有一致
- F12: 会话级 Plan Mode：用户发送 `/plan` 后，本会话仅向模型暴露只读三工具，直到用户发送 `/do`
- F13: 用户发送 `/do` 后，本会话恢复全套已注册工具
- F14: `/plan` 与 `/do` 本身不作为普通聊天内容发给模型时可剥离命令前缀；切换后界面有明确模式提示（如「计划模式 / 执行模式」）
- F15: 替换第二章「只执行第一个工具 + 强制二次纯文本且禁工具」的编排；本轮以多轮自主循环为准（纯文本无工具时仍一回合结束）
- F16: OpenAI 兼容与 Anthropic 两条协议均能跑通本轮循环（工具定义、流式工具调用解析、多轮回写）
- F17: TUI 展示循环进度与工具过程（迭代进度、工具名/状态/结果摘要、流式正文、取消与停止原因）

## 非功能需求

- N1: 继续以 TypeScript 命令行程序交付，接入 Agent Loop 后仍可在常见桌面终端启动使用
- N2: 循环中的模型错误、工具失败、未知工具、取消、触顶等均不得导致进程崩溃；向用户给出可读中文说明
- N3: 取消信号应在合理时间内生效（正在执行的工具可完成当前一次或尽快中止后停循环，不得无视取消一直跑到上限）
- N4: 事件流与循环控制分离，便于日后换 UI 或加日志订阅而不改循环核心
- N5: 多工具并发仅限只读；副作用串行，避免同批写文件/命令互相踩踏
- N6: 开发/验收默认仍优先 DeepSeek（OpenAI 兼容）；Anthropic 有密钥时补验循环与工具
- N7: 中文界面文案与中文代码注释（与项目约定一致）
- N8: 本轮端到端应能验证：多步工具自主循环完成一项小任务，而无需用户逐步催促

## 不做的事

- 不实现权限系统（工具级授权、审批策略、沙箱策略升级等）
- 不实现上下文压缩 / 自动摘要裁剪长历史
- 不实现用户交互式确认（执行危险工具前弹确认框等）
- 不新增工具种类（仍用第二章六个工具；本轮改的是循环与编排）
- 不实现子 Agent / 多 Agent 编排
- 不实现 MCP 接入
- 不改变工作区边界与「命令不经确认即可执行」的既有安全基线（本轮也不做确认，但也不扩展权限模型）
- 不做 GUI；仅终端 TUI 事件展示增强

## 验收标准

- AC1: 一次用户任务中，可观察到多次「模型回合 + 工具执行」自主衔接，无需用户逐步催促即可推进（对应 F1、F15）
- AC2: 当模型某次回复不再调用工具时，循环结束并展示最终文本（对应 F2）
- AC3: 将迭代上限临时设为较小值（或构造长任务）时，触顶停止且有「达到迭代上限」类说明（对应 F3）
- AC4: 循环进行中按 Esc，循环停止并提示已取消；空闲时 Esc 仍返回会话列表（对应 F4）
- AC5: 连续两次未知工具名后循环停止，并说明因未知工具停止（可用测试替身/注入验证）（对应 F5）
- AC6: 模拟流错误或工具链不可恢复错误时，循环停止、中文错误可见、进程不退出（对应 F6）
- AC7: 订阅方可只通过事件流观察到文本、工具调用、工具结果、进度（及可得的 Token 用量），UI 不依赖循环内部私有状态（对应 F7、F8）
- AC8: 流式过程中界面持续出现文本增量；同一次响应结束后循环能基于完整工具调用列表做分支（有工具则执行，无则结束）（对应 F9）
- AC9: 同批含多个只读工具时存在并发执行迹象（总耗时明显小于严格串行之和，或事件时间戳重叠）；含副作用工具时按串行顺序完成（对应 F10）
- AC10: 多轮工具结果写入历史并落盘，重启或重新打开会话可见工具过程（对应 F11）
- AC11: `/plan` 后模型侧仅能使用三只读工具；试图调用写/命令类应不可用或被拒绝且不影响「只读计划」目标（对应 F12）
- AC12: `/do` 后恢复全工具；界面显示当前为计划/执行模式（对应 F13、F14）
- AC13: DeepSeek（OpenAI 兼容）上完成至少一次多步自主循环；Anthropic 有密钥时补做同等验证（对应 F16）
- AC14: TUI 可见迭代进度、工具过程摘要、流式正文与停止原因（完成/取消/触顶/错误等）（对应 F17）
- AC15: 用真实小任务（如「读取某文件并基于内容再读另一处」）一次发送后，Agent 自主完成多步，无需中途人工逐步指令（对应 N8）
