# Hook Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。

## 实现完整性

- [x] 同时写了事件和动作的规则能被加载。缺事件、缺动作，或事件名不在九个之内，启动失败，错误里有文件和原因（验证：临时 YAML 加载，观察退出码与文案）（AC1）
- [x] 同一事件在用户级、项目级、本地级各有一条规则时，三条都执行，顺序是用户、项目、本地。后一份不会取消前一份（验证：三份各记一条日志，看顺序）（AC2）
- [x] 一条不合法规则使启动退出码非 0，且不进入对话。运行中命令失败或超时后，当前任务仍继续，日志里有失败原因（验证：坏文件启动一次；超时命令打桩一轮）（AC3）
- [x] 只跑一次的规则在同一会话里第二次触发时，动作和拦截都不再发生。离开会话后该标记消失。同一进程内再次进入会重新执行（验证：同一会话触发两次，离开后再进入触发一次）（AC4）
- [x] 进入会话触发 `session_start`。离开会话触发 `session_end`，注入的提示词消失，会话存档里没有这段文字。再次进入时提示词不会自己出现（验证：进出会话各看一次事件和提醒）（AC5）
- [x] 普通用户输入触发 `turn_start`，任务停止时触发 `turn_end`。`/help`、`/clear`、`/status` 不触发回合事件。用户消息和助手消息写入时触发对应消息事件。环境提醒和注入文本不触发消息事件（验证：打桩事件列表）（AC6）
- [x] 精确条件只命中完全相同的工具和参数。带 `*` 的条件能命中一组命令或路径。`git status` 不命中 `git status -sb`。其它事件写了条件则启动失败。同一条规则不能同时写「全部满足」和「任一满足」（验证：匹配断言 + 坏文件启动）（AC7）
- [x] `pre_tool` 写了拒绝说明且命中时，工具没有执行，权限确认没有出现，工具结果是按顺序拼起来的拒绝说明，该规则的动作仍然执行。没写拒绝说明时，工具继续进入权限判断。其它事件带拒绝说明则启动失败（验证：打桩闸门调用次数和工具结果）（AC8）
- [x] `pre_tool` 没有拦截时，默认档下本应询问的命令仍然询问，确认前没有副作用（验证：触发一次需确认的命令）（AC9）
- [x] shell 命令和 HTTP 请求的输出出现在日志里，不出现在会话存档和后续模型请求中（验证：读日志、读会话文件、看下一轮提醒）（AC10）
- [x] 注入提示词出现在后续每一次模型请求的环境提醒里，会话存档中没有这段文字。离开会话后再对话，提醒里不再有它（验证：连续两轮提醒 + 读存档 + 再进入）（AC11）
- [x] 子 Agent 动作触发时，日志写明尚未实现。没有新的对话开始，当前任务不因此停止（验证：打桩日志和会话数量）（AC12）
- [x] 未写超时时，命令在 30 秒后被中止并记日志。写成 0 或负数则启动失败。写了拒绝说明的规则，或注入提示词，若标记为异步，启动失败。异步的 shell 或 HTTP 发出后，当前回合继续，不等待它结束（验证：短睡眠对比耗时；坏超时与异步标记启动失败）（AC13）
- [x] `compact` 在压缩开始时触发。压缩仍会继续。带拒绝说明的 `compact` 规则使启动失败（验证：观察压缩事件与坏文件）（AC14）

## 集成

- [x] 工具拦截发生在权限询问之前。拦截时闸门不被调用（验证：打桩 `check` 次数为 0）（AC8、AC9）
- [x] 只有进入对话循环的输入才有回合事件。本地命令没有（验证：`/status` 与普通文本各发一次，对比事件）（AC6）
- [x] 注入文本位于提醒中 Skill 目录之后、工作区路径之前，且不写入会话文件（验证：看请求消息顺序并读存档）（AC11）
- [x] 本地级声明文件不在版本跟踪范围内（验证：`git check-ignore` 命中 `hooks.local.yaml`）（F2）

## 编译与测试

- [x] `npm run typecheck` 退出码 0
- [x] 本步临时验证脚本通过（跑完删除）（AC15）
- [x] lint（如有）通过；无则跳过

## 端到端场景

- [x] 场景 1：三份声明各有一条 `session_start` 注入。进入会话后，下一轮模型请求的提醒里按用户、项目、本地的顺序出现三段文字，会话文件里没有这些文字
- [x] 场景 2：`pre_tool` 拒绝 `rm *`，并另有一条不拒绝的格式化命令。模型调用 `rm -rf` 时工具未执行、没有权限确认、结果里有拒绝说明，格式化命令仍写了日志。调用 `git status` 时仍走权限询问
- [x] 场景 3：只跑一次的注入在同一会话第二次回合不再追加。离开会话再进入后，提醒里没有旧注入，该规则会再执行一次
