# Hook Spec

## 背景

MewCode 已经能对话、调工具、做权限判断，也能在压缩上下文时发出通知。格式化、按参数拦截、往后续请求里补一段提示，这些时机固定的事仍要人盯着做。

## 目标

- 在生命周期的固定时刻自动执行事先声明的规则。一条规则由事件、可选条件、动作组成。条件省略就是无条件。事件和动作必须有
- 九个事件。会话：进入，以及离开或进程退出。回合：用户回车到这次任务结束；`/help`、`/clear`、`/status` 这类本地命令不算一轮。消息：用户消息、助手消息。工具：执行前、执行后。系统：上下文压缩开始，只观察
- 只有工具执行前可以拦截。规则上写了拒绝说明并且条件命中，工具不执行，这段说明作为工具结果交回模型，也不再弹出权限确认。动作照常执行。没写拒绝说明就只做动作。拦截之后若放行，仍按当前权限档决定放行、询问或拒绝
- 条件只用于两个工具事件，匹配方式与现有权限相同：精确相等，或带 `*` 的 glob。多条条件要么全部满足，要么任一满足，不混用
- 四种动作：执行 shell 命令、注入提示词、发 HTTP 请求、启动子 Agent。子 Agent 这一步只占位，不真正运行。命令和 HTTP 的输出只记日志。注入的提示词放进后续每次模型请求的环境提醒，不写入会话存档，离开会话后消失
- 可以声明只跑一次、后台异步、命令超时。只跑一次记在当前进程内存里，按「规则 + 会话」计，重启后重新计数。会拦截的规则不能异步
- 用户级、项目级、本地级三份声明都加载，按这个顺序执行，互不覆盖。任一文件里有一条不合法规则，启动失败并指出文件和原因。运行中动作失败只记日志，不打断主流程
- 不做子 Agent 的真实运行、只跑一次标记的磁盘持久化，以及规则之间的显式优先级。多条规则按文件中的先后顺序执行

## 功能需求

### 规则与加载

- F1: 一条规则包含事件、可选条件、动作。事件和动作必须有。条件省略表示无条件触发。
- F2: 规则来自三份声明：用户级、项目级、本地级。三份都加载，按用户、项目、本地的顺序执行，互不覆盖。文件不存在视为没有规则。
- F3: 加载时集中校验。任一文件里有一条不合法规则，进程启动失败，退出码非 0，错误指出文件和原因。运行中某个动作失败只记日志，其余规则和 Agent 主流程继续。
- F4: 同一时刻命中的多条规则按 F2 的顺序全部执行。没有优先级字段。标记为只跑一次的规则，在「该规则 + 该会话」已经执行过后，本会话内整条跳过，不再执行动作，也不再拦截。计数只在当前进程内存里，离开会话或进程退出后清除。重启后重新计数。

### 事件

- F5: 事件只有这九个：`session_start`、`session_end`、`turn_start`、`turn_end`、`user_message`、`assistant_message`、`pre_tool`、`post_tool`、`compact`。其它名字启动失败。
- F6: `session_start` 在进入一个会话时触发，包括新建和再次打开。`session_end` 在离开该会话或进程退出时触发。离开会话时，清掉该会话注入的提示词和只跑一次标记。
- F7: 一轮指用户一次回车到这次任务结束。`turn_start` 在这次输入真正进入对话循环时触发。`turn_end` 在这次任务停止时触发，包括完成、取消、出错和达到轮次上限。`/help`、`/clear`、`/status` 这类不进入对话循环的本地命令不触发回合事件。
- F8: `user_message` 在用户消息写入会话时触发。`assistant_message` 在助手消息写入会话时触发。环境提醒、注入的提示词和 Hook 日志不触发消息事件。
- F9: `pre_tool` 在工具执行前、权限判断前触发。`post_tool` 在工具有了结果之后触发。`compact` 在上下文压缩开始时触发，只观察，不能拦截。

### 条件

- F10: 只有 `pre_tool` 和 `post_tool` 可以写条件。其它事件写了条件，启动失败。
- F11: 条件匹配工具名，以及该工具的命令文本或文件路径，规则与现有权限相同：完全相同，或带 `*` 的 glob。`*` 匹配任意长度，其余字符按字面量。不支持反向和正则。
- F12: 多条条件必须声明「全部满足」或「任一满足」之一。不能在同一条规则里混用。只有一条条件时，两种声明效果相同。

### 拦截

- F13: 只有 `pre_tool` 可以带拒绝说明。其它事件带了拒绝说明，启动失败。`compact` 不能拦截。
- F14: `pre_tool` 命中且写了拒绝说明时，工具不执行，也不再弹出权限确认。全部命中的拒绝说明按规则顺序拼成工具结果交回模型。这些规则的动作仍然执行。没写拒绝说明的命中规则只执行动作，不拦截。
- F15: 没有任何命中的 `pre_tool` 规则拦截时，继续走现有权限档：放行、询问或拒绝。Hook 放行不能代替权限。

### 动作

- F16: 动作有四种：执行 shell 命令、注入提示词、发送 HTTP 请求、启动子 Agent。命令和 HTTP 请求的输出只记日志，不进入模型上下文，也不写入会话消息。
- F17: 注入的提示词追加到该会话的环境提醒中，出现在后续每一次模型请求里，不写入会话存档。同一会话内保留，离开会话或进程退出后消失。
- F18: 子 Agent 动作可以被声明和加载。触发时只记一条「尚未实现」的日志，不启动另一个对话，也不中断主流程。
- F19: 可以标记只跑一次、后台异步、命令超时。超时默认 30 秒，规则可另行指定正数。超时后中止该命令或请求并记日志。
- F20: 写了拒绝说明的规则，以及注入提示词，不能标记为异步。这样标记则启动失败。shell 和 HTTP 可以异步：主流程不等待它们结束。异步动作失败同样只记日志。

## 非功能需求

- N1: 启动失败要立刻可见：规则不合法时进程退出码非 0，错误信息包含文件和原因，进程不进入对话界面。
- N2: 运行中的动作失败、超时、子 Agent 占位，都只记日志。当前任务继续，不因为 Hook 结束对话循环。
- N3: 命令和 HTTP 的输出、以及 Hook 失败原因，都能在日志里看到。这些内容不出现在会话存档和模型上下文里。
- N4: 会拦截的规则在权限询问之前完成。拦截时用户看不到权限确认，工具的副作用尚未发生。
- N5: 注入的提示词只存在于后续模型请求的环境提醒中。会话存档里读不到这段文字。
- N6: 只跑一次的计数和注入文本随会话离开或进程退出消失，不写入磁盘。
- N7: 异步动作不挡住当前回合。主流程在动作发出后继续，不等待命令或请求结束。
- N8: 可离线验证：规则校验、条件匹配、拦截是否跳过权限询问、注入是否进入提醒，不依赖真实模型和真实终端就能检查。

## 不做的事

- 不真正启动子 Agent，也不把子 Agent 的结果送回主对话
- 不把「只跑一次」的标记写入磁盘，重启后不保留
- 不做规则之间的显式优先级、权重或手动排序字段。顺序就是用户级、项目级、本地级文件里的先后
- 不做反向匹配和正则。条件只有精确相等和带 `*` 的 glob
- 不在会话、回合、消息和 `compact` 上写条件。这些事件只能无条件触发
- 不让 `compact` 或 `post_tool` 拦截工具或取消压缩
- 不把命令输出、HTTP 响应或 Hook 日志写进会话存档，也不放进模型上下文
- 不让 Hook 放行代替权限档。未拦截的工具仍按现有权限处理
- 不因为 Hook 动作失败、超时或尚未实现的子 Agent 而结束当前任务
- 不在这一步提供 Hook 的市场、远程下发或版本管理

## 验收标准

- AC1（F1、F5）：一条同时写了事件和动作的规则能被加载。缺事件、缺动作，或事件名不在九个之内，启动失败，错误里有文件和原因。
- AC2（F2、F4）：同一事件在用户级、项目级、本地级各有一条规则时，三条都执行，顺序是用户、项目、本地。后一份文件不会取消前一份。
- AC3（F3、N1、N2）：一条不合法规则使启动退出码非 0，且不进入对话。运行中命令失败或超时后，当前任务仍继续，日志里有失败原因。
- AC4（F4、N6）：只跑一次的规则在同一会话里第二次触发时，动作和拦截都不再发生。离开会话或进程退出后，该标记消失。重启后同一条规则会再执行。
- AC5（F6、F17、N5）：进入会话触发 `session_start`。离开会话触发 `session_end`，注入的提示词消失，会话存档里没有这段文字。再次进入同一会话时，提示词不会自己出现。
- AC6（F7、F8）：普通用户输入触发 `turn_start`，任务停止时触发 `turn_end`。`/help`、`/clear`、`/status` 不触发回合事件。用户消息和助手消息写入会话时触发对应消息事件。环境提醒和注入文本不触发消息事件。
- AC7（F9–F12）：`pre_tool` 和 `post_tool` 上，精确条件只命中完全相同的工具和参数；带 `*` 的条件能命中一组命令或路径。`git status` 不命中 `git status -sb`。其它事件写了条件，启动失败。同一条规则不能混用「全部满足」和「任一满足」。
- AC8（F13、F14、N4）：`pre_tool` 写了拒绝说明且命中时，工具没有执行，权限确认没有出现，工具结果是按顺序拼起来的拒绝说明。该规则的动作仍然执行。没写拒绝说明时，工具继续进入权限判断。其它事件带拒绝说明，启动失败。
- AC9（F15、N4）：`pre_tool` 没有拦截时，默认档下本应询问的命令仍然询问，确认前没有副作用。
- AC10（F16、N3）：shell 命令和 HTTP 请求的输出出现在日志里，不出现在会话存档和后续模型请求中。
- AC11（F17、N5）：注入提示词出现在后续每一次模型请求的环境提醒里，会话存档中没有这段文字。离开会话后再对话，提醒里不再有它。
- AC12（F18、N2）：子 Agent 动作触发时，日志写明尚未实现。没有新的对话开始，当前任务不因此停止。
- AC13（F19、F20、N7）：未写超时时，命令在 30 秒后被中止并记日志。写成 0 或负数则启动失败。写了拒绝说明的规则，或注入提示词，若标记为异步，启动失败。异步的 shell 或 HTTP 发出后，当前回合继续，不等待它结束。
- AC14（F9）：`compact` 在压缩开始时触发。它不能取消压缩，也不能写成带拒绝说明的规则。
- AC15（N8）：规则校验、glob 匹配、拦截后不询问、注入进入提醒，能在不调用真实模型、不打开真实终端的情况下检查通过。
