# MewCode 结构化系统提示 Spec

## 背景

前三章已具备流式对话、六工具、Agent Loop 与 Plan Mode。当前几乎没有结构化系统提示：模型主要靠工具 schema 与用户话自行发挥，关键约定（优先专用工具、编辑前先读、模式约束等）缺少稳定承载；也未区分可缓存的稳定指令与每轮变化的环境/模式信息，不利于省钱省延迟，也难验证缓存是否命中。

## 目标

- 将全局指令按职责拆成可拼装模块，按优先级组成完整系统提示，便于后续插入新模块
- 稳定指令（及工具描述）走可缓存通道；环境信息与运行时补充走消息通道，避免破坏稳定前缀
- 在工具描述与全局指令中双重强化关键行为规则，提高遵守率
- 用带特殊标签的伪用户消息在运行中注入补充指令；不落盘、不充当用户提问
- 会话级开关（如计划模式）按轮次控频注入：首轮完整、默认每 5 轮加强、其余精简
- 可选模块（自定义指令 / Skill / 长期记忆）预留槽位，本轮内容为空
- 解析 API 缓存命中字段并暴露给上层；准备典型场景做人工定性对比
- 本轮不做：项目指令文件加载、自动记忆、真实 MCP、自动化评估

## 功能需求

- F1: 提供系统提示拼装能力：按优先级顺序拼接多个指令模块，模块之间以空行分隔，输出完整系统提示文本
- F2: 固定模块按以下优先级从前到后排列：身份 → 系统约束 → 任务模式 → 动作执行 → 工具使用 → 语气风格 → 文本输出；其后接环境信息
- F3: 在固定模块与环境信息之后，预留可选模块槽位（顺序固定）：自定义指令 → 已激活的 Skill → 长期记忆；本轮这三项内容为空，但不破坏拼接顺序与扩展点
- F4: 稳定内容（固定模块正文，以及发往模型的工具描述中与规则相关的稳定文案）作为可缓存前缀的一部分；环境信息与按轮次变化的补充指令不进入该稳定前缀
- F5: 身份模块说明助手身份与使命（终端 AI 编程助手 MewCode）
- F6: 系统约束模块说明安全与边界（含工作区范围、不编造文件内容等关键约束）
- F7: 任务模式模块说明计划模式与执行模式的行为差异及切换方式（与现有 `/plan`、`/do` 语义一致）
- F8: 动作执行模块说明如何推进任务（推理—行动—观察等），并强化「编辑/改写前必须先读」等约定
- F9: 工具使用模块说明工具选用原则，并强化「优先使用专用工具（读/写/改/搜/命令），避免用通用命令代替专用能力」等约定
- F10: 语气风格与文本输出模块分别约束沟通语气与面向用户的输出形式（如简洁、结构化、中文为主等，与项目约定一致）
- F11: 环境信息至少包含：工作区根路径、当前日期/时间（或等价可读时间）、当前操作系统类信息；作为变化内容注入，不写入稳定前缀
- F12: 六个核心工具的面向模型描述中，再次写明与 F8/F9 对应的关键规则（与全局指令双重强化）
- F13: 运行时补充指令以伪用户消息形式注入，内容包裹在约定特殊标签内（如 `<system-reminder>…</system-reminder>`）；全局指令中明确：标签内是系统提醒，不得当作用户提问来回复
- F14: 上述补充消息仅在发往模型的请求中临时插入，不写入会话落盘历史，TUI 默认不展示为用户消息
- F15: 当会话处于计划模式时，按 Agent 迭代轮次注入模式提醒：第 1 轮完整；之后每隔 N 轮（默认 N=5）注入加强版；其余轮次注入精简版；执行模式可不注入或仅在需要时注入极简说明
- F16: OpenAI 兼容协议：保持稳定 system 前缀以利于自动前缀缓存；从响应用量中解析缓存命中/未命中相关字段（若存在）并向上暴露
- F17: Anthropic 协议：对稳定 system（及协议允许的工具定义缓存标记）使用可缓存配置；解析响应中的缓存相关用量字段并向上暴露
- F18: 上层（事件流或等价通道）能获知本轮请求的缓存命中信息（有则展示/记录数值；协议未返回时明确为不可用而非假数据）
- F19: 提供一组文档化的典型对比场景说明，供人工定性评估「有结构化提示 vs 无/弱提示」时的工具遵守与任务质量（本轮不要求自动化打分）
- F20: 接入后，Agent Loop 每次调用模型前使用拼装后的系统提示与临时补充消息；纯文本与多工具循环行为仍符合第三章既有停止/取消/模式过滤语义

## 非功能需求

- N1: 继续以 TypeScript 命令行程序交付；接入后仍可在常见桌面终端启动使用
- N2: 提示拼装与注入失败时不得拖垮进程；应回退到可继续对话的安全行为，并给出可读中文说明（或可观测的错误事件）
- N3: 稳定前缀在同一进程、同一工具集与同一固定模块版本下应保持字节级稳定（不含环境信息与轮次提醒），以便前缀缓存可命中
- N4: 补充消息与环境信息不得破坏稳定前缀的连续性（即不得插在稳定 system 正文中间）
- N5: 缓存命中字段以各协议实际返回为准；无字段时标记为不可用，禁止伪造命中数据
- N6: 开发/验收默认优先 DeepSeek（OpenAI 兼容）观察 `prompt_cache_hit_tokens` / `miss`；Anthropic 在具备密钥时验证显式缓存标记与用量字段
- N7: 中文界面文案、中文模块正文与中文代码注释（与项目约定一致）
- N8: 本轮交付应能用真实 API 做至少一次「连续两轮请求」观察缓存命中变化（DeepSeek）；并完成人工定性对比记录入口（文档场景列表即可）

## 不做的事

- 不加载项目指令文件（如 `AGENTS.md` / 仓库内自定义指令文件自动读入）
- 不实现自动记忆写入/检索（长期记忆槽位本轮恒空）
- 不实现真实 Skill 发现与激活（Skill 槽位本轮恒空）
- 不接入真实 MCP
- 不做自动化评估流水线或打分器（仅文档化人工对比场景）
- 不改变第三章 Agent Loop 的停止条件、取消、多工具调度与 Plan 工具过滤语义（本轮只叠加提示与注入）
- 不把 `<system-reminder>` 补充消息写入会话落盘或默认展示为用户气泡
- 不做可配置工作区根（仍为启动时当前工作目录）
- 不做 GUI

## 验收标准

- AC1: 系统提示由多模块按约定优先级拼成，模块间空行分隔；顺序为身份→系统约束→任务模式→动作执行→工具使用→语气风格→文本输出→环境信息→（空的）自定义指令/Skill/记忆槽位（对应 F1–F3）
- AC2: 固定模块正文在相同配置下连续两次拼装结果一致；环境信息可随工作区/时间变化而不改固定模块正文（对应 F4、F11、N3）
- AC3: 拼装结果中可识别身份、约束、计划/执行模式说明、动作执行与工具使用规则、语气与输出要求（对应 F5–F10）
- AC4: 环境信息含工作区根路径及时间、系统类信息；且不插入稳定固定模块正文中间（对应 F11、N4）
- AC5: 六个工具描述中仍可见「优先专用工具」「编辑前先读」类强化表述（对应 F12）
- AC6: 请求中存在带约定标签的补充消息；全局指令中说明不得将其当作用户提问回复（对应 F13）
- AC7: 补充消息不出现在会话落盘 JSON 的用户消息中；TUI 不把它显示成普通用户气泡（对应 F14）
- AC8: 计划模式下：第 1 轮为完整提醒；第 2–4 轮为短提醒；第 6 轮（默认 N=5）再次出现加强提醒（可用日志/调试输出或请求装配快照验证）（对应 F15）
- AC9: DeepSeek 连续两轮相近请求时，用量中能读到缓存 hit/miss 字段（命中值可为 0，但字段可解析）；上层事件或日志能展示（对应 F16、F18、N6、N8）
- AC10: Anthropic 在有密钥时：稳定 system 带可缓存标记；响应用量中的缓存相关字段可解析并向上暴露；无密钥则标记跳过（对应 F17、F18）
- AC11: 协议未返回缓存字段时，上层显示「不可用」类状态，不伪造命中数（对应 N5）
- AC12: 存在文档化的人工对比场景列表（至少 3 个典型任务场景）（对应 F19）
- AC13: 接入后 Agent 仍可完成多步工具循环；`/plan` 工具过滤与 Esc 取消等第三章行为不被破坏（对应 F20）
- AC14: 拼装/注入异常时进程不崩，有可读中文错误或可继续的回退（对应 N2）
