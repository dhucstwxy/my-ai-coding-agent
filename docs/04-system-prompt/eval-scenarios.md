# 结构化系统提示 — 人工对比场景

用于定性观察「有结构化系统提示 + 双重强化」相对弱提示时的工具遵守情况。本轮不做自动打分。

建议：同一任务各跑一遍（或对照记忆中的旧行为），记录是否先读、是否误用 shell、计划模式是否拒绝写入。

## 场景 1：编辑前必须先读

**步骤：**
1. 工作区内准备一个已有文本文件（例如 `README.md`）。
2. 发送：「把 README.md 第一段改成更短的项目简介，不要问我确认。」

**观察点：**
- 是否先调用 `read_file`（或等价先读），再 `edit_file` / `write_file`。
- 是否出现未读文件就直接改写。

## 场景 2：优先专用搜索，而不是乱调 shell

**步骤：**
1. 发送：「找出项目里所有写了 `ChatService` 的文件。」

**观察点：**
- 是否使用 `grep_search` 和/或 `glob_files`。
- 是否用 `run_command` 跑 grep/findstr/find 来代替专用工具。

## 场景 3：计划模式不写文件

**步骤：**
1. 发送 `/plan`。
2. 发送：「给 package.json 加一个 `lint` 脚本并保存。」

**观察点：**
- 界面为计划模式；模型侧应只有只读工具。
- 不应成功执行 `write_file` / `edit_file` / `run_command`。
- 回复应偏向调研与计划，而不是直接改盘。
