# 上下文管理 Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。

## 实现完整性

- [ ] Token 近似估算可用（验证：对已知字符串跑 `estimateChars`，结果为 `ceil(len/4)`）
- [ ] 无 usage 锚点时按全量消息估算；有锚点时仅增量累加（验证：单元脚本或临时 tsx）
- [ ] 单条工具结果 > 20K tokens 时落盘，消息变为预览+路径（验证：构造超大 tool 消息跑 micro，检查文件与 content）
- [ ] 同助手回合工具结果合计 > 40K 时从大到小依次落盘（验证：同组多条超限，较大者优先被替换）
- [ ] 重量切分保留约 10K tokens 且至少 5 条近期原文（验证：对长消息列表跑 `splitForCompact`）
- [ ] 切点左侧用户消息优先划入 recent（验证：故意在切点放 user，断言它在 recent）
- [ ] 摘要 Prompt 含禁止调工具、先草稿后正文、五段标题（验证：检查 `buildSummaryPrompt` 输出字符串）
- [ ] 摘要请求不携带工具（验证：假 Provider 收到的 `tools` 为空或不存在）
- [ ] 压缩结果含边界提示（验证：auto 成功后消息中出现「重读文件 / 勿脑补」类中文提示）
- [ ] `/compact` 与 `/compact 备注` 可触发手动压缩且不把命令写入用户任务消息（验证：打桩 ChatService）
- [ ] 配置 `context_window` 生效；缺省 128000（验证：临时 YAML 加载 + 未配置断言默认）
- [ ] 连续 3 次摘要失败后自动重量压缩停止；成功 `/compact` 后恢复（验证：假 Provider 抛错三次再成功一次）
- [ ] 摘要失败时会话消息与失败前一致（验证：失败前后 `get(session).messages` 深比较）

## 集成

- [ ] AgentLoop 每次模型请求前先跑管线（验证：假 Pipeline/日志顺序：micro → 可选 auto → streamChat）
- [ ] Micro 有变更或 Auto 成功后会话文件已更新（验证：读 `~/.mewcode/sessions/{id}.json` 或测试 Store）
- [ ] 工具结果文件落在 `sessions/{sessionId}/tool-results/`（验证：路径与文件存在）
- [ ] usage 返回后估算锚点更新（验证：一轮假 usage 后增量估算变化符合预期）
- [ ] TUI/事件能展示 compact 开始/成功/失败/熔断（验证：订阅事件或界面观察）
- [ ] 轻量预防在熔断期间仍执行（验证：熔断后仍能 spill 超大 tool 结果）

## 编译与测试

- [ ] `npm run typecheck` 通过
- [ ] 项目相关单元/脚本验证通过（本步新增的 tsx 断言均绿）
- [ ] lint 检查通过（如有配置）

## 端到端场景

- [ ] 场景 1（轻量预防）：在真实会话中让工具返回超大输出 → 下一轮请求前消息变为预览+路径，且 tool-results 下有全文文件；对话可继续
- [ ] 场景 2（自动重量压缩）：将上下文窗口配小（或堆足够历史）使估算超过「窗口−13K」→ 自动出现压缩提示 → 历史变为摘要+边界+近期原文 → 后续对话仍可用
- [ ] 场景 3（手动压缩）：输入 `/compact 保留接口约定` → 看到压缩结果提示 → 会话已缩短 → 备注影响可见于摘要或至少请求已带备注（可通过日志/打桩确认）
- [ ] 场景 4（熔断）：人为让摘要连续失败 3 次 → 界面提示熔断 → 之后自动不再重量压缩 → `/compact` 成功后自动压缩恢复
- [ ] 场景 5（失败原子性）：摘要调用失败 → 刷新/重读会话，消息列表与压缩前一致
