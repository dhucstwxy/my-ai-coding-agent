# 上下文管理 Spec

## 背景

MewCode 目前每次请求都会把会话里的全量消息发给模型。长任务里工具结果会快速堆高 token，容易逼近甚至超过上下文窗口，导致请求失败或会话无法继续。已有字符级工具结果截断和 token usage 观测，但没有「按预算管理上下文」的能力。

## 目标

- 在有限 token 预算内支持长时间连续工作，避免因上下文溢出而中断
- 用两层策略：轻量预防（大工具结果存盘）+ 重量兜底（结构化摘要）
- 优先压缩工具结果；用户原始消息尽量原文保留
- 支持自动触发与手动触发；摘要连续失败可熔断，避免死循环
- 压缩结果永久写回会话，重启后行为一致

## 功能需求

- F1 轻量预防（单条工具结果）：单条工具结果估算超过 20K tokens 时，将全文写入该会话的 tool-results 目录；对话消息中只保留短预览与文件路径，并永久写回会话。
- F2 轻量预防（同消息合计）：同一条助手回合内、多条工具结果合计超过 40K tokens 时，按体积从大到小依次执行 F1，直到合计降到阈值以下（或无可再压项）。
- F3 请求前管线：每次向模型发请求前，先执行轻量预防（F1/F2），再判断是否需要重量兜底（F4）。
- F4 重量兜底（自动）：当估算上下文用量超过「窗口 − 13K」时，自动触发结构化摘要压缩；从对话尾部按 token 往回数，保留约 10K tokens 的近期原文，且至少保留 5 条消息；更早的消息由摘要替代，并永久写回会话。
- F5 结构化摘要：摘要由当前对话同一模型生成，请求不携带任何工具；提示词禁止调用工具，并要求先写分析草稿再写正式摘要，草稿用完即弃。正式摘要按五段组织：会话意图与目标 / 关键决策与约束 / 已完成工作 / 当前状态与待办 / 相关文件与路径。
- F6 压缩边界提示：重量压缩完成后，在摘要与近期原文之间插入一条边界消息，明确提示：需要文件细节时应重新读取文件，不要根据摘要臆造代码。
- F7 用户消息保全：重量压缩选择可摘要区间时，尽量不改写用户原始消息；用户消息优先留在近期原文侧，或原样保留在未被替换的部分中（不以摘要改写用户原文为目标）。
- F8 手动压缩：用户可通过 `/compact` 触发重量压缩；可附带可选备注（注入摘要提示词）。手动触发时安全余量为 3K；用户执行该命令时，即使未过阈值也允许执行一次重量压缩。
- F9 Token 近似估算：不实现精确分词计数；以最近一次接口返回的 usage 为锚点，仅对增量内容按字符数近似折算 tokens。
- F10 窗口配置：每个 provider/model 可配置上下文窗口大小；未配置时默认 128000。
- F11 熔断：重量摘要连续失败 3 次后，本会话停止自动重量压缩；用户成功执行一次 `/compact`，或开启新会话后恢复。轻量预防不受熔断影响。
- F12 压缩可见性：自动或手动压缩发生时，向用户展示可感知的状态提示（开始/成功/失败/已熔断），避免静默改写历史。

## 非功能需求

- N1 行为可预期：同一会话、相同消息与配置下，轻量预防的存盘替换结果应确定；重量摘要内容可随模型变化，但触发条件、保留策略与写回结构应稳定。
- N2 失败可恢复：摘要请求失败不得损坏会话：要么完整写回压缩结果，要么保持压缩前状态；不得留下半截替换。
- N3 开销可控：轻量预防为本地文件与消息改写，不额外调用模型；重量摘要每次触发至多一次模型调用（不含后续正常对话请求）。
- N4 可配置：窗口大小等关键阈值应能通过配置调整，并有合理默认值，无需改代码即可适配不同模型。
- N5 兼容现有会话：对尚未压缩过的旧会话，首次请求即按新管线处理；不要求迁移工具。

## 不做的事

- 不实现精确 tokenizer / 按模型分词表计数
- 不做摘要策略的机器学习或自动调参优化
- 不提供「从压缩前快照一键还原全文历史」
- 不在本步做跨会话的全局记忆库 / RAG 长期记忆
- 不单独引入更便宜的 compact 专用模型配置（与对话同模型）
- 不改动现有工具结果字符级截断逻辑的职责边界（压缩管线叠加上去，不在本步重做整套截断策略）
- 不实现除 `/compact` 以外的压缩相关斜杠命令；熔断恢复仅通过成功的 `/compact` 或新会话

## 验收标准

- AC1（F1）：构造单条超大工具结果（估算 > 20K tokens）后发起请求，会话中该结果变为预览 + 路径，且对应全文文件存在于该会话的 tool-results 目录。
- AC2（F2）：同一助手回合内多条工具结果合计 > 40K 时，体积更大的结果被优先存盘，直到合计降到阈值下或无可再压项。
- AC3（F3）：任意正常对话请求前都会先跑轻量预防，再评估重量兜底（可通过日志/状态提示或测试钩子观测顺序）。
- AC4（F4）：将估算用量推过「窗口 − 13K」后，自动发生重量压缩；会话中较早消息被摘要替代，尾部保留约 10K tokens 且至少 5 条原文消息。
- AC5（F5）：摘要内容包含约定的五个固定部分；摘要请求不暴露可用工具，且提示词含「禁止调工具 / 先草稿后正文」。
- AC6（F6）：重量压缩后的会话中，摘要与近期原文之间存在边界提示消息（含「勿按摘要脑补代码、需细节请重读文件」之意）。
- AC7（F7）：压缩后抽查：仍保留在原文区的用户消息内容与压缩前一致（未被摘要改写）。
- AC8（F8）：输入 `/compact`（可带备注）可触发重量压缩；手动路径使用 3K 安全余量；未过阈值时执行命令仍会尝试压缩一次。
- AC9（F9）：在已有上次 usage 锚点时，仅增量变化会导致估算更新；无精确 tokenizer 依赖。
- AC10（F10）：配置某模型上下文窗口后按该值计算阈值；未配置时按 128000。
- AC11（F11）：连续 3 次摘要失败后，后续自动请求不再触发重量压缩；成功 `/compact` 或新会话后自动压缩恢复。轻量预防在熔断期间仍可用。
- AC12（F12）：压缩开始/成功/失败/熔断时，用户能在界面看到对应提示。
- AC13（N2）：故意让摘要调用失败时，会话消息与压缩前一致（无部分写回）。
