# MewCode 权限系统 Spec

## 背景

前几章已经能多轮调用六个工具，文件路径也做了工作区前缀检查。命令执行仍没有不可关闭的危险命令拦截，也没有可配置的放行、询问、拒绝规则。用户无法在严格、默认、放行之间切换信任等级，规则没写明时也不能由人当场决定。权限被拒绝时，应让模型看到失败并改策略，而不是把整轮任务停掉。

## 目标

- 执行前用内置正则黑名单拦截已知高危命令；这层不能被配置或权限档位放开
- 文件读写路径必须落在项目目录内；先解析符号链接，再做前缀判断，防止逃逸
- 用「工具名(模式)」规则声明 allow、ask、deny；支持精确匹配和 glob
- 规则分用户级、项目级、本地级三份配置，读取时合并；层级只决定写入位置，不改变判断优先级
- 判断时 deny 优先于 ask，ask 优先于 allow，与规则写在哪一层无关
- 权限档位为严格、默认、放行：只改变「没有规则明确命中」时的默认结果，不改写已写明的规则。严格为拒绝，默认为询问，放行为放行。新会话从默认档开始，可用会话内命令切换，不落盘
- 需要询问时，用户可选拒绝、仅本次放行、本会话放行、永久放行。本会话放行只记在内存；永久放行写入本地级规则，且只记下这次调用的精确参数
- 黑名单和路径沙箱在所有档位、所有放行选择之前生效
- 权限拒绝把结构化失败交回模型，Agent Loop 不因此结束
- 本轮不做网络限制、资源配额、审计日志

## 功能需求

- F1: 每次工具真正执行前，按固定顺序做权限判断：危险命令黑名单、路径沙箱、合并后的规则、当前权限档位；只有前两层都通过，才看规则和档位
- F2: 黑名单只作用于命令执行。用内置正则在执行前拦截已知高危命令，至少包括：删除根目录或用户主目录、格式化磁盘、关机或重启、把下载内容直接送进 shell 执行。命中后拒绝执行。这层不能被规则、档位或用户放行绕过
- F3: 路径沙箱作用于带文件路径的操作（读文件、写文件、改文件，以及搜索时给出的路径）。相对路径相对项目目录解析；先解析符号链接，再判断是否仍在项目目录内。越界则拒绝。这层同样不能被规则、档位或用户放行绕过。按模式找文件仍限制在项目目录内
- F4: 规则写成「工具名(模式)」，工具名只使用现有六个：`read_file`、`write_file`、`edit_file`、`run_command`、`glob_files`、`grep_search`。命令工具的模式匹配命令文本；文件类工具的模式匹配路径。支持精确匹配，也支持带 `*` 的 glob
- F5: 每条规则的结果是 `allow`、`ask`、`deny` 之一
- F6: 规则来自三份 YAML：用户级、项目级、本地级。读取时合并成一个集合。本地级位于当前项目但不进入版本库。三层同时存在时全部参与判断
- F7: 对同一次调用，在所有命中的规则里，`deny` 优先于 `ask`，`ask` 优先于 `allow`。规则写在哪一层不改变这个优先级。没有任何规则命中时，才使用当前档位的默认结果
- F8: 权限档位有三档，且只影响「没有规则明确命中」的调用，不改写已写明的 `allow`、`ask`、`deny`。严格档未命中则拒绝；默认档未命中则询问；放行档未命中则放行。默认档有一处例外：无副作用的只读工具未命中规则时直接放行，见 F17
- F9: 新会话从默认档开始。用户可用会话内命令在严格、默认、放行之间切换；切换只影响当前会话，不写入配置。界面能看出当前档位
- F10: 判断结果为询问时，暂停该次工具执行，把工具名和参数展示给用户，并提供四个选择：拒绝、仅本次放行、本会话放行、永久放行。在用户选择前不执行该工具
- F11: 仅本次放行只放行这一次调用，不记住。本会话放行记住「该工具 + 这次的精确参数」，同一会话内再次出现相同调用时不再询问，进程退出后失效。永久放行把同样的精确规则以 `allow` 写入本地级配置；更宽的模式只能由用户手改规则，不能由这次确认自动放宽
- F12: 用户在确认时选择拒绝，只拒绝这一次调用，不写入永久拒绝规则
- F13: 黑名单或路径沙箱已经拒绝的调用，不再进入询问，也不能被本次、本会话或永久放行变成成功执行
- F14: 任一权限拒绝都变成结构化失败交回模型，说明拒绝原因（黑名单、越界、规则拒绝、档位拒绝或用户拒绝）。Agent Loop 不因此结束，模型可以改策略后再调用工具
- F15: 权限判断通过后，工具本身原有的失败行为保持不变（例如文件不存在、命令非零退出、编辑匹配失败）
- F16: 三份规则都不存在或为空时，系统仍可运行，并完全按当前档位处理未命中调用
- F17: 默认档下，无副作用的只读工具（`read_file`、`glob_files`、`grep_search`）在没有规则命中时直接放行，不再询问，避免每次读取都打断确认；有副作用的工具（`write_file`、`edit_file`、`run_command`、MCP 工具）仍按默认档询问。只读与否以工具自身的无副作用标记为准。严格档和放行档不受本例外影响

## 非功能需求

- N1: 继续以现有终端程序交付。接上权限判断后，仍能在常见桌面终端里启动和使用
- N2: 黑名单、沙箱、规则拒绝和用户拒绝都不得让进程崩溃。失败信息用可读中文说明原因
- N3: 规则文件缺失、为空或某条格式不合法时，不拖垮启动。不合法的条目跳过或整份文件拒绝加载，并给出可读说明；其余合法规则仍然生效
- N4: 权限判断本身应在工具开始执行前完成。除了等待用户确认之外，不得因为规则匹配而长时间挂起
- N5: 等待用户确认时，用户仍能拒绝本次调用，或用既有方式取消整个任务。取消任务后不再执行该工具
- N6: 本地级规则不进入版本库。永久放行写入失败时，本次调用不得假装已经永久记住，并提示用户写入失败
- N7: 符号链接解析失败或无法确认路径仍在项目内时，按越界拒绝，而不是放行
- N8: 界面文案和代码注释使用中文
- N9: 本轮至少能在本地验证：高危命令被黑名单拦住、越界路径被沙箱拦住、默认档下未命中规则会询问、用户拒绝后循环仍可继续

## 不做的事

- 不做网络请求限制，也不拦截命令里的普通联网行为，除非它已经落在危险命令黑名单里
- 不做 CPU、内存、磁盘或调用次数之类的资源配额
- 不做审计日志，不单独记录每次允许或拒绝的历史文件
- 不把命令的全部文件副作用纳入路径沙箱。命令仍可能通过切换目录等方式影响项目外路径。本轮只保证带路径参数的文件工具不能越界，并用黑名单拦截已知高危命令
- 不根据一次确认自动放宽成通配规则。本会话和永久放行只记精确参数
- 不把权限档位写入配置，也不把用户当次拒绝写成永久 `deny`
- 不提供独立的规则编辑界面。除了永久放行追加一条精确 `allow` 之外，规则增删改靠手改 YAML
- 不替换现有的计划模式。计划模式仍只暴露只读工具，权限系统在此之上再判断能否执行
- 不改变 Agent Loop 的既有停止条件。权限拒绝只是一次工具失败，不是循环停止
- 不做操作系统级隔离或容器沙箱
- 不做图形界面

## 验收标准

- AC1: 同一次调用先经过黑名单和路径沙箱，这两层拒绝后不会再出现询问，也不会执行工具（对应 F1、F13）
- AC2: 在放行档、且存在一条会放行该命令的规则时，黑名单中的高危命令仍然被拒绝，原因能看出是黑名单（对应 F2）
- AC3: 读、写、改文件以及带路径的搜索，在路径越出项目目录时被拒绝。已存在的符号链接若解析后落在项目外，同样被拒绝（对应 F3、N7）
- AC4: 一条精确规则只命中相同工具和相同参数；一条带 `*` 的规则能命中对应的一组命令或路径（对应 F4、F5）
- AC5: 用户级、项目级、本地级同时存在时都会参与判断。本地级文件不在版本库跟踪范围内（对应 F6、N6）
- AC6: 同一调用同时命中低层的 `allow` 和另一层的 `deny` 时，结果是拒绝。同时命中 `allow` 和 `ask` 时，结果是询问（对应 F7）
- AC7: 没有任何规则命中时，严格档直接拒绝，默认档询问，放行档直接放行；默认档下只读工具（read_file / glob_files / grep_search）未命中则直接放行，不询问。已写明的 `deny` 在放行档仍拒绝，已写明的 `allow` 在严格档仍放行（对应 F8、F17）
- AC8: 新会话处于默认档。切换档位的命令只影响当前会话，重启后的新会话回到默认档，界面能看到当前档位（对应 F9）
- AC9: 需要询问时，界面展示工具名和参数，并给出拒绝、仅本次、本会话、永久四个选择；做出选择前工具没有执行（对应 F10）
- AC10: 仅本次放行之后，同一会话里再次出现相同调用仍会询问。本会话放行之后，相同调用不再询问，新会话又会询问（对应 F11）
- AC11: 永久放行后，本地级规则里出现一条对应该工具和精确参数的 `allow`。它不会变成带 `*` 的更宽规则。写入失败时有明确提示，且不会当成已经永久生效（对应 F11、N6）
- AC12: 用户在确认时拒绝后，工具不执行，本地级规则不新增 `deny`（对应 F12）
- AC13: 权限拒绝后，模型能收到包含拒绝原因的失败结果，当前任务的循环不因此结束，后续仍可再次调用工具（对应 F14、N2）
- AC14: 权限已放行时，文件不存在或命令非零退出仍按工具自身的失败返回，而不是报成权限错误（对应 F15）
- AC15: 三份规则都不存在时可以启动。默认档下一次普通命令会进入询问，而不是崩溃（对应 F16、N3）
- AC16: 规则文件里有一条格式不合法时，进程仍可启动，并有可读说明；同文件中的合法规则仍然生效（对应 N3）
- AC17: 等待确认时，拒绝本次调用不会执行工具；取消整个任务后该工具也不执行（对应 N5）
