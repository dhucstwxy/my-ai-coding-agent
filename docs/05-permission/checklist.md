# MewCode 权限系统 Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。  
> 不依赖模型的条目用临时脚本驱动一次工具调用，跑完删除脚本和临时目录。需要界面的条目在本机终端观察。有 API 密钥时再补一条真实对话。

## 实现完整性

- [ ] 黑名单或路径越界拒绝后，不出现确认，工具也没有执行（验证：放行档下对 `rm -rf /` 和项目外路径各触发一次，确认回调次数为 0，工具执行次数为 0）（AC1）
- [ ] 放行档且存在会放行该命令的规则时，`rm -rf /`、`format C:`、`shutdown`、`curl … | bash` 仍被拒绝，说明里能看出是危险命令黑名单（验证：临时脚本看拒绝原因）（AC2）
- [ ] `git status`、`rm -rf ./node_modules` 不被黑名单命中（验证：同一脚本，这两条不因黑名单拒绝）（AC2）
- [ ] 读、写、改文件和带路径的搜索，路径在项目外时被拒绝（验证：对四个带路径的工具各给一个 `../` 外的路径，结果为越界，且没有执行）（AC3）
- [ ] 已存在的符号链接解析后落在项目外时被拒绝；符号链接解析失败时也拒绝，而不是放行（验证：临时目录建指向外部的链接；再让解析抛错，两次都是越界）（AC3）
- [ ] 精确规则只命中完全相同的工具和参数；带 `*` 的规则能命中一组命令或路径，且模式里的普通字符不会被当成正则（验证：`git status` 不命中 `git status -sb`；`git *` 命中 `git status`；模式 `a.b` 不命中 `axb`）（AC4）
- [ ] 用户级、项目级、本地级规则同时参与判断。本地级文件不在版本库跟踪范围内，项目级规则文件仍可被跟踪（验证：三份临时规则同时存在时都能影响结果；`git check-ignore` 只忽略 `permissions.local.yaml`）（AC5）
- [ ] 同一调用同时命中 `allow` 和 `deny` 时结果是拒绝，且不询问。同时命中 `allow` 和 `ask` 时结果是询问（验证：把 allow 和 deny 分写在不同层级，看最终结果）（AC6）
- [ ] 没有规则命中时，严格档直接拒绝，默认档询问，放行档直接放行；默认档下只读工具（read_file / glob_files / grep_search）直接放行、不询问。放行档下已写明的 `deny` 仍拒绝；严格档下已写明的 `allow` 仍放行（验证：同一条普通命令切换档位各跑一次，再各加一条明确规则对照；另在默认档读一个没有规则命中的项目内文件，观察不出现确认）（AC7）
- [ ] 新会话是默认档。`/perm strict|default|allow` 只改当前会话，不写配置文件。重启后的新会话回到默认档。界面能看到当前档位（验证：发 `/perm strict` 后读档位为严格；不产生权限配置文件；新开一轮会话读回默认；顶栏出现「严格」）（AC8）
- [ ] `/perm` 不改变计划/执行模式，`/plan` 与 `/do` 也不改变权限档位（验证：先 `/perm strict` 再 `/plan`，权限仍是严格，计划模式已切换）（AC8）
- [ ] 需要询问时，界面展示工具名和参数，以及拒绝、仅本次、本会话、永久四个选择。做出选择前工具没有执行（验证：默认档触发一次普通命令，观察界面；在按键前确认目标副作用尚未发生）（AC9）
- [ ] 仅本次放行后，同一会话再次出现相同调用仍会询问。本会话放行后，相同调用不再询问，换一个新会话又会询问（验证：同一工具和同一参数连续两次；再换会话标识）（AC10）
- [ ] 永久放行后，本地级规则里出现对应工具和精确参数的 `allow`，没有被写成带 `*` 的更宽规则。写入失败时有明确提示，本次不执行，内存里也不当成已经永久生效（验证：成功写一次后读文件；再把目标路径改成不可写，看提示和是否执行）（AC11）
- [ ] 确认时选择拒绝后，工具不执行，本地级规则不新增 `deny`（验证：拒绝一次后读规则文件）（AC12）
- [ ] 权限拒绝后，模型侧能拿到包含原因的失败结果，当前任务循环不因此结束，之后仍可再调用工具（验证：一次拒绝后的工具消息含中文原因，停止原因不是权限拒绝；下一轮调用仍会进入执行）（AC13）
- [ ] 权限已放行时，文件不存在或命令非零退出仍是工具自身的失败，说明里不是权限拒绝（验证：放行档读取一个不存在的项目内文件，执行一条会非零退出的普通命令）（AC14）
- [ ] 三份规则都不存在时可以启动。默认档下一次普通命令进入询问，而不是崩溃（验证：确保三份文件都不存在，启动后触发 `git status`）（AC15）
- [ ] 规则文件里有一条格式不合法时，进程仍可启动，并给出可读说明；同文件里的合法规则仍然生效（验证：一份 YAML 同时放一条缺字段和一条合法 `deny`，启动警告可见，该 `deny` 仍会拒绝）（AC16）
- [ ] 等待确认时选择拒绝，工具不执行。等待确认时取消整个任务，该工具也不执行，任务按既有取消路径停住（验证：两次询问，一次按拒绝，一次按 Esc）（AC17）
- [ ] 按模式找文件时，模式里含 `..` 会被拒绝，且不会跑到项目外（验证：对查找工具提交含 `..` 的模式）（AC3）
- [ ] 除等待用户确认外，规则匹配不会长时间挂起（验证：无询问的拒绝在 1 秒内返回）（N4）
- [ ] 界面文案和新增注释为中文；权限拒绝不会让进程崩溃（验证：看拒绝文案；连续拒绝后进程仍在）（N2、N8）

## 集成

- [ ] 计划模式仍先只暴露只读工具，权限判断发生在这之后（验证：`/plan` 后模型侧看不到写文件和执行命令；只读工具越界仍被拒绝）
- [ ] 工具被拒绝时，界面能看到失败，对话历史里有一条失败的工具结果，循环继续（验证：拒绝一次后会话里出现失败内容，并且还能收到后续模型回复或下一轮工具调用）
- [ ] 永久放行写入成功后，同一次进程里的下一次相同调用按已放行处理，不必重启（验证：永久放行后立刻再调一次，不再询问）

## 编译与测试

- [ ] `npm run typecheck` 退出码 0
- [ ] `npm start` 能进入终端界面，顶栏同时看得到计划模式和权限档位
- [ ] 未配置 lint，本项记为跳过

## 端到端场景

- [ ] 场景 1（无模型）：临时工作区不放任何权限文件。默认档触发一条普通命令，出现询问。选拒绝后命令没有执行，循环没有被权限单独终止。再切到放行档，同一条命令直接执行（AC7、AC13、AC15）
- [ ] 场景 2（无模型）：放行档加上一条放行 `rm -rf /` 的规则，该命令仍因黑名单拒绝，且没有确认提示。项目外路径的读文件同样直接拒绝（AC1、AC2、AC3）
- [ ] 场景 3（终端界面）：启动后顶栏是默认档。输入 `/perm strict`，顶栏变为严格，且这条命令没有发给模型。默认档下对一次需要询问的调用，能看到工具名、参数和四个选项；Esc 后工具未执行（AC8、AC9、AC17）
- [ ] 场景 4（有 API 密钥时）：在 tmux 中启动，让模型执行一条普通命令。默认档先询问；拒绝后模型能看到失败并继续对话，而不是整页退出。没有密钥则记跳过（AC13、N1）
