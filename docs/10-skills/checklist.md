# Skill Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。

## 实现完整性

- [x] 合法 Skill 能被收录；缺名字、缺一句话说明或名字含非法字符时跳过并给出原因，其它 Skill 仍在。大小写不同的名字视为同一个（验证：临时目录解析后看收录结果与警告文案）（AC1）
- [x] 短命令在正文激活前就可调用。传入一段文本后，钉住的说明里占位符全部变成这段文本；不传参数时占位符为空（验证：先查命令存在，再激活后看提醒文本）（AC2）
- [x] 目录型 Skill 激活后，上下文有入口正文和同包文件位置；模板、示例、脚本、参考文档的全文不在上下文里，脚本未被执行，附属文件也没有各自变成 Skill（验证：加载结果文本 + 进程未启动该脚本）（AC3）
- [x] 同名 Skill 同时在项目、用户、内置时，生效顺序为项目、用户、内置。同一层级两个同名时进程退出码非 0，错误含该名字。单个损坏文件被跳过，其余仍可用（验证：三份临时目录对照 + 故意重名启动）（AC4）
- [x] 未激活时，对话上下文里每个 Skill 只有名字和一句话说明，没有操作说明正文（验证：打桩一轮，检查提醒文本）（AC5）
- [x] 用加载工具或短命令激活后，完整说明出现在当轮环境上下文最显眼处，下一轮仍在。两个 Skill 可同时激活。共享模式的结果写入主历史。钉住的说明本身不在会话存档里（验证：连续两轮提醒 + 读会话文件）（AC6）
- [x] `/clear` 后面界面为空，会话存档仍在，已激活 Skill 全部消失。新会话不带上一会话的激活。名为 `clear` 的 Skill 不能抢走清屏命令（验证：clear 后读文件、再发一句看提醒里没有正文）（AC7）
- [x] 独立模式结束后，主历史只有摘要，没有那段独立对话的中间消息。历史条数为 `0` 时独立对话看不到主历史；为 `2` 时能看到最近 2 条。负数为该 Skill 被跳过（验证：打桩循环的输入消息和主会话新增条数）（AC8）
- [x] 指定了模型时，独立模式整段使用该模型，共享模式从激活起使用该模型。配置里没有该模型时，这次执行失败并说明原因，会话模型不变（验证：打桩看到的模型名 + 未知模型时无请求）（AC9）
- [x] 两个写了白名单的 Skill 同时激活时，可用工具是交集。没写白名单的不参与收窄。交集为空时只剩加载工具。未激活带白名单的 Skill 时，工具集合与没有 Skill 时相同，且加载工具始终在（验证：打桩本轮工具名列表）（AC10）
- [x] 白名单指向不存在的工具时，启动失败，退出码非 0，错误同时含 Skill 名字和工具名字。回车前重扫发现同样问题时同样退出（验证：临时 Skill 启动一次、运行中改文件再回车一次）（AC11）
- [x] 白名单留下的工具若按当前权限档本应询问或拒绝，仍然询问或拒绝（验证：默认档下触发一次需确认的命令，确认前没有副作用）（AC12）
- [x] 不重启，修改说明或正文后，下一次回车前目录说明更新；已激活 Skill 的下一轮钉住正文是新内容。新增合法 Skill 后，下一次回车前出现对应短命令（验证：改文件前后各发一次，对比提醒和命令表）（AC13）
- [x] `help`、`plan`、`do`、`compact`、`permission`、`session`、`memory`、`status` 的行为与接入前一致。名为 `help` 的 Skill 仍可通过加载工具激活。`/review` 走 review Skill，不再发送原先那条固定审查提示（验证：打桩 `/review` 的用户任务不是旧固定句，`/help` 仍列出命令）（AC14）
- [x] 内置 `commit`、`review`、`test` 默认可被短命令激活。项目级或用户级同名能盖住内置样板。`review` 只有只读工具；`commit` 和 `test` 含执行命令和只读查看（验证：无项目覆盖时三个命令可用；加上项目同名后生效的是项目正文）（AC15）

## 集成

- [x] 回车前先刷新 Skill 目录，再分发命令。刷新发现致命错误时进程退出，而不是把该行送给模型（验证：打桩退出码，Provider 无调用）（AC11）
- [x] 短命令进入主循环的是替换前的用户任务文本，不是整行斜杠命令（验证：`/commit 写说明` 进入循环的文本是「写说明」）（AC2、AC6）
- [x] 加载工具不受白名单移除；计划模式仍先限制只读，再与白名单取交集（验证：计划模式加只读白名单时，写工具不可见，加载工具仍在）（AC10）
- [x] `/clear` 不删除、不截断会话文件（验证：clear 前后文件字节内容仍含原消息）（AC7）

## 编译与测试

- [x] `npm run typecheck` 退出码 0
- [x] 本步临时验证脚本通过（跑完删除）（AC16）
- [x] lint（如有）通过；无则跳过

## 端到端场景

- [x] 场景 1：启动后上下文里能看到 `commit`、`review`、`test` 的名字和说明，看不到它们的操作正文。执行 `/review 看风险` 后，下一轮提醒最前面是 review 的完整说明，且占位符已换成「看风险」
- [x] 场景 2：再激活第二个 Skill，两个说明同时钉住。`/clear` 后界面空、存档还在、两段说明都消失
- [x] 场景 3：独立模式 Skill 带 `history: 0` 跑完后，主会话只多出摘要。把白名单改成一个不存在的工具后，下一次回车进程退出，错误里有 Skill 名和工具名
