# Skill Spec

## 背景

MewCode 已经能对话、调工具、走斜杠命令。重复操作（提交、审查、跑测试）仍要用户每次重写提示词。系统提示里虽有 Skill 槽位，但还没有可复用的操作包，也没有「先看见名字、要用再加载全文」的机制。

## 目标

- 把可复用的 AI 操作写成独立文档：元信息加操作说明
- 启动和每轮对话里，模型只看到有哪些 Skill、各自做什么；真正要用时再加载完整说明
- 加载后的说明钉在当轮环境上下文最显眼的位置，并且每轮都重新放上，多个 Skill 可以同时生效
- 项目级高于用户级，用户级高于内置；同名按这个顺序覆盖。单个文件解析失败就跳过，不拖垮其它 Skill
- 两种跑法：一种留在当前对话里，结果写进主历史；另一种另开一段对话，跑完只把摘要送回主对话，并按非负整数带入最近若干条历史，`0` 表示不带
- 写了工具白名单就收窄当前可用工具。多个带白名单的 Skill 同时生效时取交集；都没写则不收窄。启动时白名单点到不存在的工具，进程立即失败。负责加载 Skill 的工具是系统级的，不受白名单限制
- 成功收录的 Skill 自动成为斜杠短命令。每次回车前重新扫描，有变化就更新目录和短命令。`/clear` 清界面，并丢掉本会话已激活的 Skill，不改会话存档
- 会话控制类短命令保留：`clear`、`help`、`plan`、`do`、`compact`、`permission`、`session`、`memory`、`status`。其余同名（如现有的 `review`）由 Skill 接管
- 内置三个样板：`commit`、`review`、`test`
- 不做 Skill 的市场分发和版本管理

## 功能需求

### 定义与存放

- F1: 一个 Skill 由元信息和正文组成。元信息放在文档开头，正文是发给模型的操作说明。
- F2: 元信息包含：唯一名字、一句话说明、可见工具白名单、执行模式（共享或独立）、独立模式带入的历史条数、可选的指定模型。白名单可省略，省略表示不收窄。执行模式省略时视为共享。历史条数省略时视为 `0`。模型省略时使用当前会话所用模型。
- F3: 名字只作短命令标识：大小写不敏感，登记为小写；只含小写字母、数字和连字符。缺名字、缺一句话说明，或名字不合法，视为这个 Skill 解析失败。
- F4: 正文中的参数占位符会被本次调用传入的整段文本替换，可出现多次。没有传入参数时，占位符变为空。
- F5: 目录型 Skill 是一个能力包：入口文档带元信息和操作说明，同目录可有模板、示例、辅助脚本和参考文档。激活时只注入入口正文；其余文件不整包进入上下文，加载结果里给出它们的位置，供模型用现有工具按需读取。加载时不自动执行脚本。
- F6: 三级存放，优先级为项目高于用户、用户高于内置。合并后同名只保留更高优先级的那一个。
- F7: 同一层级里名字重复，启动立即失败并指出重复的名字。单个文件或目录解析失败则跳过该 Skill，并给出可读原因，不阻断其它 Skill。
- F8: 目录内的模板、示例、脚本和参考文档不会被当成独立 Skill。只有带合法元信息的入口文档才会进入目录。

### 两阶段加载与激活

- F9: 启动后，以及每次用户回车前的目录刷新后，对话里只注入已收录 Skill 的名字和一句话说明，不注入正文。
- F10: 完整操作说明只在两种情况下读入并激活：模型调用系统级加载工具，或用户调用该 Skill 的短命令。
- F11: 已激活 Skill 的完整说明放在当轮环境上下文最显眼的位置，每轮重新放入。多个 Skill 可同时激活。`/clear` 清掉界面，并丢掉本会话已激活的 Skill；会话存档保持不变。新开会话不带着上一次的激活。
- F12: 成功收录后即注册斜杠短命令，不必等正文被激活。短命令可带参数，参数按 F4 替换后再执行。

### 执行模式

- F13: 共享模式在当前对话中执行，本轮及之后的结果留在主历史里。激活期间操作说明保持钉住，直到被 `/clear` 或新会话清掉。
- F14: 独立模式另开一段对话跑完，中间消息不写入主会话存档，只把最终摘要写回主历史。带入历史条数为非负整数，表示主对话里最近的多少条消息；`0` 表示不带。负数视为该 Skill 解析失败。
- F15: 指定了模型时，只影响这个 Skill 的执行：独立模式整段使用该模型；共享模式从这次激活起使用该模型，直到该 Skill 不再处于激活。多个已激活 Skill 指定了不同模型时，以最后一次激活的为准。配置里找不到该模型时，这次执行失败并说明原因，不静默改用别的模型。

### 工具白名单

- F16: 白名单收窄模型当前能看见、能调用的工具。只对写了白名单的已激活 Skill 取交集；没写白名单的不参与收窄。没有任何已激活 Skill 写白名单时，不收窄。交集为空时，只剩系统级加载工具。
- F17: 启动时，或回车前重扫时，任一已收录 Skill 的白名单指向当前不存在的工具，进程立即失败退出，错误里写明 Skill 名字和工具名字。
- F18: 负责加载 Skill 的工具是系统级的，任何白名单都不能把它拿掉。
- F19: 白名单不代替权限。留在白名单里的工具仍按当前权限档和规则决定放行、询问或拒绝。

### 短命令、热更新与样板

- F20: 每次用户回车前重新扫描三级目录。收录结果或文件内容有变化时，更新目录、一句话说明和短命令。已激活 Skill 若磁盘上的正文变了，下一轮钉住的说明用新内容。扫描期间新增的未知工具名按 F17 处理。
- F21: 下列短命令始终是会话控制命令，不被 Skill 覆盖：`clear`、`help`、`plan`、`do`、`compact`、`permission`、`session`、`memory`、`status`。同名 Skill 仍可收录，仍可通过加载工具激活，但不能抢走这些短命令。其余同名短命令由 Skill 接管，包括现有的 `review`。
- F22: 内置三个样板，均可被更高级别的同名 Skill 覆盖：`commit` 用共享模式，根据当前改动准备提交；`review` 用共享模式，审查当前工作并给出风险与建议；`test` 用共享模式，运行测试并汇报结果。三者都写明白名单：提交与测试包含执行命令和只读查看；审查只有只读查看。

## 非功能需求

- N1: 未激活时省 Token：对话上下文里每个 Skill 只有名字和一句话说明，正文留在磁盘上。
- N2: 致命错误要立刻可见：白名单指向不存在的工具，或同一层级名字重复时，进程退出码非 0，错误信息包含冲突的 Skill 名字；未知工具还要包含那个工具名字。
- N3: 单点失败不拖垮整体：某个 Skill 解析失败时跳过并给出可读原因，其余 Skill 照常收录、注册短命令。
- N4: 热更新不需要重启：改完 Skill 文件后，下一次用户回车前就能看到新的目录、说明或短命令。已激活 Skill 的正文若变了，下一轮钉住的说明用新内容。
- N5: 激活说明不污染会话存档：钉住的操作说明只出现在每轮环境上下文里，不把正文反复写成会话消息。独立模式的中间消息也不写入主会话存档。
- N6: 白名单不能绕过权限：收窄之后，仍按当前权限档和规则决定放行、询问或拒绝。
- N7: 保留的会话控制命令行为不变：`clear`、`help`、`plan`、`do`、`compact`、`permission`、`session`、`memory`、`status` 的原有语义不受 Skill 影响。
- N8: 可离线验证：解析、三级覆盖、白名单交集、短命令是否被接管，不依赖真实模型和真实终端就能检查。

## 不做的事

- 不做 Skill 的市场、远程下载、安装源或版本管理
- 不做除「整段参数替换」以外的模板引擎，也不做条件分支、循环或嵌套模板
- 不在加载时自动执行能力包里的脚本
- 不把模板、示例、脚本和参考文档整包塞进上下文
- 不把已激活的操作说明写成会话消息，也不把独立模式的中间过程写入主会话存档
- 不把 Skill 激活状态写入磁盘；`/clear` 或新开会话之后需要重新激活
- 不提供单独的卸载命令。去掉激活只靠 `/clear` 或新开会话
- 不让 Skill 覆盖 `clear`、`help`、`plan`、`do`、`compact`、`permission`、`session`、`memory`、`status`
- 不把白名单做成另一套权限系统，也不让白名单绕过现有权限档和规则
- 不在本步改 `/clear` 的存档语义：仍然只清界面，不删除或截断会话文件
- 不支持运行中才连上的工具去补救启动时已经失败的白名单校验

## 验收标准

- AC1（F1–F3）：一份合法 Skill 能被收录；缺名字、缺一句话说明或名字含非法字符时，这个 Skill 被跳过并给出原因，其它 Skill 仍在。名字大小写不同视为同一个。
- AC2（F4、F12）：调用短命令并传入一段文本后，钉住的说明里该占位符全部变成这段文本；不传参数时占位符为空。短命令在正文被激活前就已经可用。
- AC3（F5、F8）：目录型 Skill 激活后，上下文里有入口正文，并有同包文件的位置；模板、示例、脚本和参考文档的全文不在上下文里，脚本没有被自动执行，这些附属文件也没有各自变成 Skill。
- AC4（F6、F7）：同名 Skill 同时存在于项目、用户、内置时，生效的是项目级，其次用户级，再次内置。同一层级两个同名 Skill 时进程退出码非 0，错误里有这个名字。单个损坏文件被跳过，其余仍可用。
- AC5（F9、N1）：未激活时，对话上下文里每个 Skill 只有名字和一句话说明，没有操作说明正文。
- AC6（F10、F11、F13、N5）：通过加载工具或短命令激活后，完整说明出现在当轮环境上下文最显眼处，下一轮仍在。两个 Skill 可同时处于激活。共享模式的结果写入主历史。这些钉住的说明本身不写入会话存档。
- AC7（F11、N7）：`/clear` 之后界面消息为空，会话存档仍在，已激活 Skill 全部消失。新开会话不带着上一会话的激活。`/clear` 的短命令仍是清屏，不会被同名 Skill 抢走。
- AC8（F14、N5）：独立模式跑完后，主历史里只有摘要，没有那段独立对话的中间消息。历史条数为 `0` 时独立对话看不到主历史；为 `2` 时能看到主对话最近 2 条。负数导致该 Skill 被跳过。
- AC9（F15）：指定了模型时，独立模式整段使用该模型；共享模式从激活起使用该模型。配置中不存在该模型时，这次执行失败并说明原因，会话模型不被偷偷换掉。
- AC10（F16、F18）：两个写了白名单的 Skill 同时激活时，可用工具是二者交集；没写白名单的 Skill 不参与收窄。交集为空时只剩加载工具。未激活任何带白名单的 Skill 时，工具集合与没有 Skill 时相同。任何收窄情况下加载工具都在。
- AC11（F17、N2）：白名单里有一个当前不存在的工具时，启动失败，退出码非 0，错误中同时有 Skill 名字和工具名字。回车前重扫发现同样问题时，同样立即失败退出。
- AC12（F19、N6）：白名单留下的工具若按当前权限档本应询问或拒绝，仍然询问或拒绝，不会因为 Skill 而直接放行。
- AC13（F20、N4）：修改已收录 Skill 的一句话说明或正文后，不重启，下一次回车前目录说明更新；若该 Skill 已激活，下一轮钉住的正文是新内容。新增合法 Skill 后，下一次回车前出现对应短命令。
- AC14（F21、N7）：`help`、`plan`、`do`、`compact`、`permission`、`session`、`memory`、`status` 的短命令行为与接入 Skill 之前一致。名为 `help` 的 Skill 仍可通过加载工具激活。`/review` 由 review Skill 接管，不再发送原先那条固定审查提示。
- AC15（F22）：内置 `commit`、`review`、`test` 三个样板默认可被短命令激活。项目级或用户级同名 Skill 能盖住内置样板。`review` 的白名单只有只读查看；`commit` 和 `test` 的白名单包含执行命令和只读查看。
- AC16（N3、N8）：解析、三级覆盖、白名单交集、短命令是否被接管，能在不调用真实模型、不打开真实终端的情况下检查通过。
