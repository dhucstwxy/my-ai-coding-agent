# 服务端长驻会话 Plan

## 架构概览

对话成为 HTTP 服务自己的资源。每一轮仍交给现在的一次性任务去跑，跑完即结束。助手循环不留在内存里。

服务进程直接读写工作区里 HTTP 专用的会话文件。终端用的是另一目录，两边互不读取。创建空对话只写文件，不启动模型。发送消息时，若这段对话已有未结束的一轮，就拒绝；否则按现有排队规则提交一轮，并带上这段对话的标识。事件流继续用现有任务的事件订阅。

| 组件 | 职责 |
| --- | --- |
| 对话目录 | 按工作区创建、列出、打开对话。只碰 HTTP 会话文件。列表按最近活动排序，标出正在进行的对话，摘要取第一句用户消息，没有则显示为新对话。打开时只返回用户消息和助手回复 |
| 任务队列 | 保持现有的单线程执行、排队上限、超时和重启恢复。新增「为某段对话提交一轮」：同一对话已有未结束轮次则拒绝，其他情况与一次性任务一样排队。进行中的判断来自未结束任务上的对话标识 |
| 无头执行 | 不改协议。它按传入的对话标识打开已有会话文件，写入这句用户消息并跑完一轮。空对话必须能被它打开 |
| HTTP 接口 | 在现有访问限制下提供创建、列出、打开和发送。发送的结果指向这一轮任务，调用方用现有事件流观看。一次性任务的接口原样保留 |
| 聊天页 | 按工作区拉对话列表，新建、打开、发送，并订阅该轮事件流。对话正忙时停在页面上，不发请求。不再把最近任务当作对话列表 |

```
创建对话
  → 解析工作区
  → 写入一条空的 HTTP 会话文件
  → 返回对话标识

发送消息
  → 确认这段对话属于该工作区，且没有未结束的一轮
  → 排入现有任务队列（带对话标识）
  → 无头执行打开会话文件并跑完这一轮
  → 现有事件流推出文本、工具和结束

重启
  → 会话文件仍在工作区，列出和打开直接读文件
  → 未结束的一轮仍走现有任务恢复，不重复写入同一句用户消息
```

## 核心数据结构

会话文件继续用无头执行已经能打开的 JSONL。服务只在创建空对话时写文件头，不自己追加消息。用户消息和助手回复仍由那一轮执行写入。

文件在 `<工作区>/.mewcode/api-sessions/<会话标识>.jsonl`。创建时只有一行：

```json
{"type":"session","id":"<会话标识>","title":"新会话","createdAt":"<UTC 时间>"}
```

会话标识沿用现有规则：以字母或数字开头，其余只含字母、数字、点、下划线和连字符，总长不超过 81。生成形式与现有会话标识相同，即 `年月日-时分秒-6位十六进制`。

### 对话摘要

列表和创建结果使用同一视图。`busy` 不落盘，读取时根据未结束任务是否带有这个会话标识来计算。`label` 也不靠文件里的标题：有用户消息时取第一句，空白折叠后最多 40 个字符，超出加省略号；没有用户消息时为「新对话」。`updatedAt` 取文件修改时间与最后一条消息时间中较晚的一个。列表按它从新到旧排列。

| 字段 | 含义 |
| --- | --- |
| `sessionId` | 会话标识 |
| `workspace` | 所属工作区的绝对路径 |
| `label` | 列表上的辨识文字 |
| `busy` | 是否有未结束的一轮 |
| `createdAt` | 创建时间 |
| `updatedAt` | 最近活动时间 |

### 对话消息

打开对话时只投影 `user` 和 `assistant`，保持文件中的顺序。`tool`、`system` 以及工具调用细节不返回。

| 字段 | 含义 |
| --- | --- |
| `role` | `user` 或 `assistant` |
| `content` | 正文 |
| `createdAt` | 写入时间 |

打开结果是摘要再加上 `messages`。

### 请求与发送结果

创建只接收可选的 `workspace`。发送接收非空 `prompt`，以及可选的 `workspace`。工作区的解析与一次性任务相同：显式路径、否则默认工作区。查找会话时只在这个工作区的 HTTP 会话目录里找；另一个工作区下同名标识视为不存在。

发送成功时返回这一轮任务的定位，方便接着用现有事件流：

| 字段 | 含义 |
| --- | --- |
| `sessionId` | 对话标识 |
| `runId` | 这一轮任务标识 |
| `status` | 与现有任务相同的状态 |
| `workspace` | 解析后的工作区 |
| `position` | 排队位置，与一次性任务相同 |

### 对话目录

```text
create(workspace) -> 摘要
list(workspace, busy_ids) -> 摘要列表
get(workspace, session_id) -> 摘要 + 消息
```

`create` 只写文件头。`get` 在文件不存在或标识不合法时失败。损坏的行跳过，不让列出或打开失败。

### 为对话提交一轮

任务队列增加一个入口，内部仍走现有的提交、持久化和恢复：

```text
submit_for_session(workspace, session_id, prompt) -> (任务, 排队位置)
busy_session_ids() -> 未结束任务占用的会话标识集合
```

同一 `session_id` 已有未结束任务时拒绝，并说明这段对话正忙。排队已满时与一次性任务一样拒绝。通过后，这一轮的会话目录固定为该工作区的 HTTP 会话目录，并带上 `session_id`。

## 模块设计

### 对话目录

**职责：** 在指定工作区的 HTTP 会话目录里创建、列出和打开对话。只写空文件头，不追加消息。列表摘要、排序和「新对话」标签都在这里算好。`busy` 由调用方传入的未结束会话标识集合填上。

**对外接口：** `create(workspace)`、`list(workspace, busy_ids)`、`get(workspace, session_id)`。标识不合法、文件不存在，或文件不在这个工作区的 HTTP 会话目录里，都失败。创建时若标识碰巧碰撞，换一个再写。损坏的行跳过。

**依赖：** 文件系统，以及现有的工作区解析。不依赖任务队列，也不依赖 worker。

### 任务队列

**职责：** 原有的提交、排队、执行、取消、事件和重启恢复保持不动。新增按对话提交一轮：同一会话标识已有未结束任务则拒绝；未结束任务达到上限则按原规则拒绝；通过后把这一轮放进同一条队列。这一轮从提交起就带上会话标识和该工作区的 HTTP 会话目录。另外提供当前未结束任务所占用的会话标识集合，供列表和打开时标记忙闲。

**对外接口：** 现有提交接口不变。新增 `submit_for_session(workspace, session_id, prompt)` 和 `busy_session_ids()`。

**依赖：** 现有 worker 客户端和运行记录。不读取会话正文。

### HTTP 接口

**职责：** 在与一次性任务相同的访问限制下暴露对话操作，并把工作区、空消息和忙闲翻译成可读的中文错误。发送成功后返回这一轮的任务标识，事件流仍走现有的任务事件地址。健康检查和一次性任务路由不改。

**对外接口：**

| 操作 | 路径 | 结果 |
| --- | --- | --- |
| 创建 | `POST /v1/sessions` | 摘要 |
| 列出 | `GET /v1/sessions` | 摘要列表 |
| 打开 | `GET /v1/sessions/{sessionId}` | 摘要加消息 |
| 发送 | `POST /v1/sessions/{sessionId}/messages` | 任务定位 |

工作区：创建和发送放在请求体，列出和打开用查询参数。缺省都走现有解析。对话正忙返回冲突，排队已满、工作区无效、消息为空、找不到对话，都与现有任务使用同一类状态码，正文用中文说明原因。

**依赖：** 对话目录、任务队列、现有的令牌校验和工作区解析。

### 聊天页

**职责：** 按工作区显示对话列表，提供新建和打开。发送成功后先显示用户消息，再订阅这一轮的现有事件流，把文本增量和工具活动画出来。返回「正忙」时只显示原因，不把这句留在对话里，也不清掉输入。页面重新打开时只根据工作区向服务要列表，不靠浏览器里保存的会话标识找回对话。

**对外接口：** 无。它只调用上面的对话接口和现有事件流。

**依赖：** HTTP 接口。不再把最近任务列表当作对话历史。

### 无头执行

**职责：** 保持现状。收到带会话标识的一轮时，打开已有的 HTTP 会话文件，写入用户消息并跑完。不新增协议，也不读取终端会话目录。

**对外接口：** 现有的运行、取消和关闭。

**依赖：** 无新依赖。它能打开对话目录写好的空文件。

## 模块交互

对话目录和任务队列互不调用。HTTP 接口按顺序串起它们。无头执行只在队列轮到这一轮时启动，并且只看见已经写好的会话文件。

**创建。** 接口先做与一次性任务相同的令牌校验和工作区解析，再叫对话目录写空文件头。不查看忙闲，也不进任务队列。返回的摘要里 `busy` 为否。

**列出和打开。** 接口解析工作区后，向任务队列要未结束任务占用的会话标识，再交给对话目录。目录只在该工作区的 HTTP 会话目录里读文件，算好排序、标签和消息投影，用这组标识填上 `busy`。文件不存在则打开失败。worker 没就绪时，列出和打开仍然成功。

**发送。** 接口确认消息非空、工作区有效，并且这段对话就在该工作区。然后调用 `submit_for_session`。队列在同一次调用里完成三件事：worker 不可用则拒绝；这个会话标识已有未结束任务则拒绝并说明正忙；未结束任务已达上限则按原规则拒绝。都通过才写入运行记录并入队。入队前不把执行权交出去，所以两次发送不会同时越过忙闲检查。

队列轮到它时，走现有的执行路径：把会话标识和 HTTP 会话目录交给无头执行。无头执行打开那个文件，写入这句用户消息，跑完一轮。文本增量、工具活动和结束都发到这一轮任务的现有事件流上。调用方拿发送结果里的任务标识去订阅；订阅晚了，仍由现有事件流先补已经发生的事件。

其他对话或一次性任务占着执行位置时，发送仍然入队等待，不返回正忙。正忙只针对同一个会话标识。

**聊天页。** 打开或更换工作区时列出对话。新建走创建，再打开该对话。选中一项时打开并画出用户消息和助手回复。发送成功后先画用户消息，再订阅该轮事件流。收到正忙时只显示原因，输入保留，对话内容不增加这句。页面不从浏览器里的标识恢复当前对话。

**重启。** 对话目录没有单独的恢复步骤，直接读工作区里的文件。未结束的一轮仍由任务队列按现有规则续跑或结束；已经写入过的那句用户消息不会再写一次。续跑期间 `busy_session_ids()` 仍包含它，再发送会被拒绝。

**一次性任务。** 提交、等待、查询、取消和事件流仍进原来的队列入口，不经过对话目录。它若把会话写进同一个 HTTP 目录，这段对话会出现在列表里；任务记下会话标识之后，列表把它标成正在进行。这不改变一次性任务接口的请求和响应。

## 文件组织

无头执行和终端会话不动。这一期只改 HTTP 服务、聊天页和对应测试。

```
server/mewcode_api/
├── session_catalog.py   — 新建。对话目录：创建空文件、列出、打开、标签和排序
├── models.py            — 修改。对话摘要、消息、创建请求、发送请求和发送结果
├── run_manager.py       — 修改。submit_for_session、busy_session_ids
├── main.py              — 修改。四个对话路由，接上现有令牌校验和工作区解析
└── static/chat.html     — 修改。对话列表、新建、打开、发送和事件流

server/tests/
└── test_api.py          — 修改。对话接口、忙闲、重启后续写、一次性任务回归

src/                     — 不改
```

会话正文仍在 `<工作区>/.mewcode/api-sessions/<会话标识>.jsonl`。运行记录仍在现有的服务数据目录。终端会话仍在 `<工作区>/.mewcode/sessions/`，没有代码去读写它。

## 技术决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 对话放在哪 | 服务进程直接读写 `<工作区>/.mewcode/api-sessions/*.jsonl` | 创建、列出和打开不需要模型，worker 未就绪时也能读。文件格式沿用无头执行已经能打开的会话头，不新增 worker 协议 |
| 空文件里的标题 | 写成现有的「新会话」 | 无头执行认这个文件头。接口上的「新对话」只在返回的 `label` 里计算，不改文件标题 |
| 一轮怎么跑 | 仍进入现有任务队列和无头执行 | 规格要求每轮跑完即结束。排队、超时、恢复、取消和事件流都不用另做 |
| 正忙怎么判断 | 未结束任务上的会话标识；检查和入队在同一次调用里完成 | 正忙只针对同一段对话。不另写锁文件。两次发送不会同时通过检查 |
| 事件流 | 发送结果返回 `runId`，订阅现有的任务事件地址 | 晚订阅、文本增量、工具活动和结束状态都已经存在 |
| 状态码 | 正忙用冲突响应；排队已满、工作区无效、消息为空、找不到对话、未授权、worker 未就绪，与一次性任务使用同一类状态码 | 调用方靠状态码区分「这段对话正忙」和「服务正忙」。正文用中文说明原因 |
| 工作区字段 | 创建和发送放在请求体；列出和打开用查询参数。缺省都走现有解析 | 与一次性任务的请求体一致，打开和列出不需要请求体 |
| 终端会话 | 不读不写 `<工作区>/.mewcode/sessions/` | 网页对话和终端对话保持独立 |
| 一次性任务写进同一目录 | 允许它出现在对话列表里，并在任务记下会话标识后标成正在进行 | 那本来就是 HTTP 会话文件。过滤它会把真实对话藏掉。一次性任务自己的接口不改 |
| 聊天页记住什么 | 可以记住工作区和访问令牌，不靠保存的会话标识决定当前对话 | 重启后只提供工作区也能找回对话 |
| 存储 | 不引入缓存或数据库 | 会话文件和现有运行记录已经满足重启后继续 |
| 幂等 | 发送消息不接受幂等键 | 规格明确不做另一套幂等协议 |
