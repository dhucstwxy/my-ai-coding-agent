# 服务端长驻会话 Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。

## 对话资源

- [ ] 在某个工作区创建对话后先不发送，再列出，能看到这段对话，并显示为新对话（验证：创建接口返回后立刻列出，对应 AC1）
- [ ] 同一工作区有两段对话时，刚有过活动的那段排在前面；工作区 A 的列表不包含工作区 B 的对话（验证：两个工作区各创建一段并比较列表，对应 AC2）
- [ ] 一轮成功后再次打开，按顺序能看到用户消息和助手回复，响应里没有工具角色的消息（验证：发送后再打开，对应 AC5）
- [ ] 不指定工作区时，新对话落在与一次性任务相同的默认工作区；把这段对话拿到另一个工作区下打开或发送，得到找不到（验证：省略工作区创建，再用另一个存在的目录去打开，对应 AC9）

## 一轮执行与事件流

- [ ] 发送一句非空消息后，正文随事件流逐步出现；会触发工具的请求能在事件流里看到工具活动（验证：订阅该轮事件，对应 AC3）
- [ ] 订阅建立在部分正文已经产生之后，仍能看到已产生的正文和最终结束状态；结束状态能区分成功、失败和取消（验证：一轮完成后再订阅事件，并分别观察成功与取消，对应 AC4）
- [ ] 再发第二句，询问第一句里约定的内容，回复能用上第一句（验证：端到端场景里用真实模型观察，对应 AC5）
- [ ] 工具调用无需确认即执行，事件里的工具名不超出六个内置工具（验证：触发一次工具调用，过程中没有审批提示，对应 AC16）
- [ ] 一轮失败时能看到可读中文原因，服务进程仍在，这段对话之后还可以再发（验证：让一轮失败后查询健康状态并再发一条，对应 AC18）

## 忙闲与排队

- [ ] 一轮尚未结束时再向同一段对话发送，被拒绝并说明正忙；该轮仍会结束，结束后可以再发一条（验证：用会停住的一轮挡住第二次发送，然后等它结束或取消后再发，对应 AC6）
- [ ] 其他对话或一次性任务正在执行时，向一段空闲对话发送会被接受并等待（验证：先占住执行位置，再向另一段空闲对话发送，得到已接受而不是正忙，对应 AC7）
- [ ] 未结束任务达到现有上限后再发送，拒绝方式与一次性任务排队已满相同（验证：把未结束任务顶到上限，比较两种发送的状态码和原因，对应 AC7）

## 访问与错误

- [ ] 工作区不存在，或消息只有空白时，请求被拒绝并给出可读中文原因，服务继续可用（验证：两种非法请求后健康检查仍成功，对应 AC8）
- [ ] 开启与一次性任务相同的访问限制后，不带凭证不能创建、列出、打开或发送；健康检查仍可访问。关闭该限制后这些操作恢复可用（验证：带与不带凭证各请求一次，对应 AC10）
- [ ] 对话列表、已保存消息和事件流里不出现配置中的密钥（验证：完成一轮普通对话后检查这三处文本，对应 AC17）

## 聊天页

- [ ] 选定工作区后能看到对话列表，能新建并打开已有消息。发送后先出现自己的消息，再逐步出现回复和工具活动（验证：在浏览器里完成新建、打开和发送，对应 AC11）
- [ ] 这段对话正忙时，页面说明正忙，这句不会成为新的一轮，输入还留着（验证：一轮未结束时在页面上再发送，对应 AC11）
- [ ] 页面文案是中文，并且不需要先记住会话标识才能看到列表（验证：新开页面只填写工作区，对应 AC11、AC12）

## 重启与隔离

- [ ] 完成至少一轮后重启服务。用新开的页面、只提供同一工作区，仍能看到该对话和已保存消息，并成功再发一条（验证：重启前后比较列表和打开结果，对应 AC12）
- [ ] 在一轮进行中重启服务。该轮按一次性任务的恢复规则续跑或结束，对话里这句用户消息只出现一次（验证：重启后续看打开结果里的用户消息条数，对应 AC13）
- [ ] 一次性任务的提交、等到结束、查询、取消和事件流各完成一次，行为与这一期之前一致（验证：跑现有一次性任务测试，对应 AC14）
- [ ] 终端里已有的对话不出现在网页列表。网页上聊过的对话不出现在终端历史里（验证：两边各有一段对话后交叉查看，对应 AC15）
- [ ] worker 未就绪时仍能列出和打开已有对话；发送会得到与一次性任务相同的未就绪拒绝（验证：用无法启动的执行端启动服务后分别列出和发送）

## 编译与测试

- [ ] 在 `server` 目录执行 `python -m unittest tests.test_api`，全部通过（验证：命令退出码为 0）
- [ ] 终端交互的启动路径没有被改成依赖新的对话接口（验证：不带对话参数的原有测试或原有启动入口仍可用）

## 端到端场景

- [ ] 场景 1：启动服务，打开聊天页，指定工作区并新建对话，发送「先记住暗号：青柠。只回复已记住」。正文逐步出现。再发送「我刚才的暗号是什么」，回复里出现「青柠」。重启服务后，新开页面只填同一工作区，仍能看到这两轮，并再发一条成功（验证：浏览器里观察列表、流式正文和重启后的历史）
- [ ] 场景 2：同一段对话还在回复时再发送一句，页面说明正忙，对话里没有多出这句。该轮结束后再发送，能够开始新的一轮（验证：浏览器里观察状态区和对话条数）
