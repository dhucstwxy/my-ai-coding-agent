# 服务端长驻会话 Spec

## 背景

HTTP 服务已经能提交一次任务，并用事件流看到文本增量和工具过程。要接着聊，调用方必须自己记住上一轮带回来的会话标识，再塞进下一次任务。服务不把「某个工作区里有哪些对话」当成可以列出、打开、续写的资源。

聊天页因此只显示最近的任务。服务重启后，对话原文还在该工作区里，但页面不能向服务要回这些对话，只能依赖浏览器里碰巧留下的标识。

工具行为保持现状：六个内置工具，调用自动放行。终端里的技能、MCP、Hooks、小组和审批不在这一期。

## 目标

- 调用方可以按工作区创建或打开一段对话，连续发送后续消息，并用事件流观察每一轮。
- 聊天页使用这套能力：列出该工作区已有对话，打开后看到已有消息，发送后看到流式输出。
- 服务重启后，仍能按工作区列出这些对话并继续发送。
- 同一段对话已有一轮在进行时，新的消息被拒绝，并说明这段对话正忙。
- 现有的一次性任务提交、等待结束、查询和事件流保持可用。

## 功能需求

- F1: 调用方可以在指定工作区创建一段新对话。创建完成后对话立刻存在，此时可以还没有任何消息，并且能被列出。
- F2: 调用方可以列出某个工作区中的对话，最近有活动的排在前面。有用户消息时，用第一句的摘要来辨识；还没有消息时，显示为新对话。列表标明哪一段正在进行。其他工作区的对话不出现。
- F3: 调用方可以打开一段对话，按顺序读到已经保存的用户消息和助手回复。事后打开不要求重放每一条工具过程。
- F4: 向一段对话发送一条非空消息后开始一轮。这一轮使用与一次性任务相同的助手行为：同一份模型配置、六个内置工具、工具自动放行，并且能利用该对话里已经保存的内容。
- F5: 这一轮用事件流推送文本增量、工具活动和结束。结束时能区分成功、失败和取消。订阅开始得晚时，仍能看到已经发生的事件和最终结束。
- F6: 同一段对话已有未结束的一轮时，再发送消息会被拒绝，并说明这段对话正忙。未结束的那一轮继续进行。
- F7: 其他对话或一次性任务占用执行位置时，新消息仍被接受，并按一次性任务现有的排队规则等待。排队已满时，拒绝方式与一次性任务相同。
- F8: 一轮成功、失败或取消之后，这段对话不再处于忙，可以再发下一条，下一条能利用此前已经保存的内容。
- F9: 服务重启后，各工作区的对话和已保存消息仍可列出、打开和续写。重启时尚未结束的一轮，按一次性任务现有的恢复规则处理，并且不会把同一句用户消息再次写入对话。
- F10: 工作区不存在或消息为空时，请求被拒绝并给出可读原因。一段对话只属于它的工作区，不能拿到另一个工作区下继续。
- F11: 未指定工作区时，使用与一次性任务相同的默认工作区。新的对话操作与一次性任务使用同一套访问限制。
- F12: 聊天页按工作区列出对话，可以新建。打开后看到已保存的用户消息和助手回复；发送后先看到自己的消息，再看到该轮的流式正文和工具活动。这段对话正忙时，页面说明正忙，并且不把这条新消息发出去。
- F13: 服务重启后重新打开聊天页，同一工作区仍能看到重启前的对话和已保存消息，并继续发送。
- F14: 一次性任务的提交、等待结束、查询、取消和事件流保持现有行为。
- F15: 这些对话与终端交互界面里的对话相互独立。网页列表不包含终端历史，网页上的对话也不进入终端历史。

## 非功能需求

- N1: 一轮的正文必须随事件流增量出现。聊天页不能等整轮结束才一次性显示回复。
- N2: 对话和已保存消息落在本机对应工作区。服务重启后，凭工作区即可找回，不依赖浏览器里残留的标识。
- N3: 同一时刻仍然只执行一轮，排队上限、单轮超时和恢复次数与一次性任务相同。
- N4: 新的对话操作使用与一次性任务相同的访问限制。未授权时拒绝创建、列出、打开和发送。健康检查仍不要求授权。
- N5: 对话路径上的工具权限不超过一次性任务：六个内置工具，自动放行，不额外扩大可操作范围。
- N6: 配置里的密钥不出现在对话列表、已保存消息或事件流中，除非用户自己把密钥写进消息。
- N7: 工作区无效、消息为空、对话正忙、排队已满、未授权或一轮失败时，调用方和聊天页都能看到可读的中文原因。单次失败不导致服务退出。
- N8: 现有只使用一次性任务的调用方无需改动。
- N9: 聊天页沿用现有本地页面，用浏览器即可完成列出、打开、发送和观看事件流。
- N10: 界面文案使用中文。

## 不做的事

- 不把助手循环留在内存里等下一句。每轮仍按一次性任务的方式跑完，再从已保存的对话继续。
- 不接入技能、MCP、Hooks、小组、子代理、斜杠命令和项目记忆。
- 不增加审批回传，也不在聊天页切换权限。工具仍自动放行。
- 不把网页对话和终端对话合并，也不改终端交互界面。
- 不移除一次性任务，不改变它现有的提交、等待、查询、取消和事件流语义。
- 聊天页不新增取消、删除、重命名、编辑历史或分叉对话。
- 打开已结束的对话时，不重放每一条工具过程。
- 不引入缓存服务或数据库，也不把现有落盘换成另一种存储。
- 不加账号体系，不做云端同步。
- 对话发送不另做一套幂等协议。

## 验收标准

- AC1: 在某个工作区创建对话后先不发送，再去列出，能看到这段对话，并显示为新对话。（F1、F2）
- AC2: 同一工作区有两段对话时，刚有过活动的那段排在前面。工作区 A 的列表不包含工作区 B 的对话。（F2、F10）
- AC3: 向一段对话发送一句非空消息后，正文随事件流逐步出现，而不是整轮结束后一次性出现；用会触发工具的请求时，事件流里能看到工具活动。（F4、F5、N1）
- AC4: 订阅建立在部分正文已经产生之后，仍能看到已经产生的正文和最终结束状态。结束状态能区分成功、失败和取消。（F5）
- AC5: 一轮成功后再次打开，能按顺序看到这句用户消息和助手回复，且不要求重放工具过程。再发第二句询问第一句里约定的内容，回复能用上第一句。（F3、F4、F8）
- AC6: 一轮尚未结束时再向同一段对话发送，被拒绝并说明正忙；该轮仍会结束。结束后可以再发一条。（F6、F8）
- AC7: 其他对话或一次性任务正在执行时，向一段空闲对话发送会被接受并等待。未结束任务达到现有上限后再发送，拒绝方式与一次性任务排队已满相同。（F7、N3）
- AC8: 工作区不存在，或消息只有空白时，请求被拒绝并给出可读中文原因，服务继续可用。（F10、N7）
- AC9: 不指定工作区时，新对话落在与一次性任务相同的默认工作区。一段对话不能换到另一个工作区下继续。（F10、F11）
- AC10: 开启与一次性任务相同的访问限制后，不带凭证不能创建、列出、打开或发送。健康检查仍可访问。关闭该限制后，这些操作恢复可用。（F11、N4）
- AC11: 聊天页选定工作区后能看到对话列表，能新建并打开已有消息。发送后先出现自己的消息，再逐步出现回复和工具活动。这段对话正忙时，页面说明正忙，这句不会成为新的一轮。（F12、N9、N10）
- AC12: 完成至少一轮后重启服务。用新开的页面、只提供同一工作区，仍能看到该对话和已保存消息，并成功再发一条。不依赖重启前页面是否留有标识。（F9、F13、N2）
- AC13: 在一轮进行中重启服务。该轮按一次性任务的恢复规则续跑或结束，对话里这句用户消息只出现一次。（F9、N3）
- AC14: 一次性任务的提交、等到结束、查询、取消和事件流各完成一次，行为与这一期之前一致。（F14、N8）
- AC15: 终端里已有的对话不出现在网页列表。网页上聊过的对话不出现在终端历史里。（F15）
- AC16: 对话中的工具调用无需确认即执行，并且不会出现六个内置工具以外的能力。（N5）
- AC17: 一轮普通对话的列表、已保存消息和事件流里不出现配置中的密钥。（N6）
- AC18: 一轮失败时能看到可读中文原因，服务进程仍在，这段对话之后还可以再发。（F8、N7）
